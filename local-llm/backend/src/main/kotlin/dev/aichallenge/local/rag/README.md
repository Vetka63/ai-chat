# RAG дня 28

Это новый доменный модуль в приложении локальной недели. Прежняя папка `rag` (Pro Git, дни 21–25) не изменяется. Корпус — предоставленные пользователем русские рассказы Warhammer. Полные тексты и фактические ответы лежат в Docker volume, не в Git.

## Карта классов

| Класс / пакет | Ответственность |
| --- | --- |
| `config/RagProperties` | Путь отдельной БД, embedding-модель, allowlist DeepSeek, флаг cloud и ключ |
| `models/Contracts` | Снимки документов/индекса, режимы, запрос, результаты и метрики |
| `corpus/CorpusService` | Строгий UTF-8, нормализация переносов, ручной начальный заголовок, дедупликация |
| `indexing/ParagraphChunker` | Границы абзацев, overlap и точные диапазоны документа |
| `indexing/IndexService` | Фоновая индексация, batches по 8, проверка identity и атомарная публикация |
| `embeddings/EmbeddingEngine` | Тестируемый порт локальных embeddings |
| `embeddings/OllamaEmbeddings` | `/api/tags` и `/api/embed`, запрет cloud-тегов и `truncate=false` |
| `retrieval/HybridRanking` | Локальный BM25 и объединение порядков с dense-поиском через RRF |
| `retrieval/RetrievalService` | Одна подготовка вопроса, проверка пространства, область поиска, threshold, бюджет, messages и hash |
| `generation/RagGenerator` | Генерация без retrieval и fallback |
| `generation/LocalRagGenerator` | Повторное использование `LocalLlmRuntime` без истории чата |
| `generation/DeepSeekRagGenerator` | Явный облачный вызов с серверным ключом и allowlist модели |
| `experiments/ExperimentService` | UUID, фоновая работа, параллельность провайдеров, независимые исходы |
| `storage/RagRepository` | SQLite, атомарное READY, синхронизация двух карточек, восстановление INTERRUPTED |
| `web/RagController` | HTTP API, диагностический поиск, сохранение ручного вывода и MD без вызова LLM |

## Индексация

1. Браузер или `scripts/import-day28.ps1` передаёт TXT через multipart. Backend не принимает произвольный filesystem path или download URL.
2. UTF-8 декодируется без молчаливой замены битых символов. BOM убирается, CRLF становится LF. Если задан `startMarker`, он должен встретиться отдельной строкой ровно один раз. Реклама до него исключается явно, не классифицируется моделью.
3. Текст сохраняется в `rag_documents`. SHA-256 относится к нормализованному тексту после исключения вступления, не исходным bytes файла.
4. `POST /indexes` создаёт BUILDING и возвращается сразу. Worker удерживает общий `GenerationGate`: индексация и генерация не конкурируют за GPU.
5. Чанки до 1400 UTF-16 символов с overlap 180 (параметры API настраиваемы) сохраняют exact substring, source, title, section, start/end и ID. Очень длинный абзац разрезается по словам. Это не размер в токенах. Короткие перекрытые места не являются отдельными новыми фактами.
6. Embedding input: название + раздел + текст. Вектора локальной `qwen3-embedding:0.6b` проверяются по числу, размерности, конечности и ненулевой норме.
7. Имя, digest, dimension и template фиксируются в индексе. Изменившийся digest отклоняет построение/поиск. Только полный индекс публикуется как READY вместе со всеми векторами одной транзакцией.

Таблицы отдельного `/app/data/rag.sqlite`: `rag_documents`, `rag_indexes`, `rag_vectors`, `rag_experiments`. Таблицы чатов дня 27 остаются в `/app/data/lab.sqlite`.

## Запрос и сравнение

1. UI сохраняет receipt запроса до POST: UUID + параметры, без секретов. Повтор того же UUID возвращает сохранённый эксперимент; другие параметры с тем же ID отклоняются.
2. Backend проверяет режим LOCAL/DEEPSEEK/COMPARE, модели и READY индекс. Cloud disabled/нет ключа не мешает LOCAL. Вторая одновременная RAG-задача отклоняется, скрытой очереди нет.
3. Локально вычисляется embedding вопроса с instruct template, проверяется то же пространство и размерность. Кеш только query-вектора (до 1000 записей) включает space и exact input. Повтор вопроса не перегружает embedding-модель; retrieval и генерация всё равно выполняются заново. При cache hit embedding API tokens текущего поиска равны 0, что явно видно в snapshot/UI/MD. Это не кеш ответов и не подстановка evaluation.
4. Все вектора выбранного индекса/рассказа ранжируются exact cosine. BM25 учитывает слова и редкие имена; упрощённое русское снятие окончаний не является полноценным морфологическим анализатором. RRF: `1/(60+denseRank) + 2/(60+lexicalRank)`; отсутствующий lexical rank даёт нулевой второй вклад. Коэффициенты фиксированы, не являются обученной оценкой уверенности.
5. Если вопрос явно называет рассказ, его первый чанк добавляется как metadata-контекст (origin=BOOK_OPENING), остальные — по RRF; простое снятие русских окончаний помогает распознать название. Это обычный текст начала документа, не эталон ответа. Общее число ограничено Top-K. Затем применяется порог **исходного cosine** и бюджет целых фрагментов. UI хранит origin и оба порядка отдельно. Порог — не вероятность. Если ничего не включено, UNKNOWN без генерации; small budget не маскируется новой попыткой поиска.
6. `SYSTEM` задаёт работу только с источниками, признание неизвестного и ссылки `[S1]`. `USER` содержит JSON QUESTION/SOURCES. Документы остаются данными, а не новыми системными инструкциями. Это снижает риск prompt injection, но не доказывает неуязвимость.
7. В COMPARE две virtual-thread задачи одновременно получают **один List сообщений**. Hash относится к общим messages, не разным HTTP envelopes с моделью и provider-specific options. Оба используют одну температуру, явный cap при его наличии и один флаг thinking; механизмы reasoning провайдеров не тождественны.
8. Каждая карточка сохраняется сразу по завершении своего провайдера, под синхронизированным read-modify-write. UI читает эксперимент polling раз в ~900 мс, без SSE. Уже готовый ответ виден, пока второй RUNNING.
9. Таймаут/пустой ответ/транспортная ошибка дают FAILED только соответствующей карточке. `length` → TRUNCATED. Завершение обеих генераций → COMPLETED; один завершённый ответ при проблеме другого → PARTIAL. **COMPLETED — выполнение, не правильность.**
10. Проверка ссылок VALID означает только, что найденные в тексте ID существуют среди переданных источников. Она не проверяет смысл утверждений. MISSING/INVALID видны явно. Облачного judge нет ни в одном режиме дня 28. Ожидания из `evaluation` не индексируются и не передаются LLM.
11. Результат, sources, ошибки и метрики сохраняются. Ручной вывод пользователя отдельный; скачивание MD не вызывает модели. После restart незавершённые записи получают INTERRUPTED, без автоматического повторения.

## Граница локальности и ограничения

LOCAL: только SQLite, Kotlin, локальные `/api/embed` и `/api/chat`; cloud adapter не вызывается. Веса и зависимости сначала скачиваются; потом для доказательства можно включить `compose.offline.yml`, где cloud false, ключ пустой, backend/Ollama только в internal Docker network. Nginx связан также с обычной сетью, чтобы localhost UI оставался доступен на Windows; он служит входным reverse proxy, не каналом внешней генерации.

COMPARE/DEEPSEEK: вопрос и найденные фрагменты передаются API DeepSeek по явному выбору пользователя. Полные книги не отправляются. Локальная стоимость — не «бесплатные вычисления», а отсутствие платы за LLM API; ресурсы компьютера всё равно расходуются.

Одна JVM, один локальный пользователь, localhost binding, без авторизации и distributed locks. Не публикуйте API в интернет. Главы не включены в checkout: на другой машине нужно импортировать свои файлы. Новая база не является физическим индексом Pro Git прошлой недели — это осознанное изменение по просьбе пользователя; если проверяющий требует старый индекс буквально, отдельно демонстрируйте прежний RAG.
