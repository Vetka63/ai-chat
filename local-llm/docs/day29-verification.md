не применять автоматически `audit fix --force`.

секрет только в Authorization и обезличенные ошибки. Пять полей оцениваются точно,

## Выявленные ограничения модели

Базовый prompt часто записывал «причина неизвестна» или гипотезу строкой вместо JSON null.
Специализация уменьшила эту ошибку, но не обеспечила безошибочность.

В holdout specialized:

- `h06`: после исправления «затронуты только 5%» модель сохранила P1 вместо P2.
  Summary также неверно утверждал, что затронуты все. Ошибка показана и не исправлялась backend.
- `h10`: каждый из трёх повторов получил context overflow: нужно 4249 токенов, окно 4096.
  Ни молчаливого обрезания, ни повторной генерации, ни cloud fallback не было.

После проверки **объёма входа**, не подбора prompt по эталонам holdout, preset изменён на 6144.
Этот новый профиль ещё не проверен живыми запросами. Промпт после holdout не менялся.
Поэтому нельзя заявить, что окончательная конфигурация уже проходит весь набор.

## Сбой инфраструктуры

В 12:21 UTC Docker VM зарегистрировала Buffer I/O errors, EXT4 aborted journal и
`Remounting filesystem read-only`. Затем запуск dockerd завершился `input/output error`.
Сообщение UI о daemon.json не доказывает синтаксическую ошибку конфигурации:
лог показывает невозможность чтения/запуска бинарного файла.

Docker DataFolder находится на C:, где после сбоя осталось примерно 2,16 GiB.
Это существенное ограничение диска; точную первопричину I/O ещё нужно подтвердить.
Не было доказательства GPU OOM в этом сбое. На момент диагностики свободно около 14 GiB RAM.
Сборка упала с Bus error, загрузка FP16 не завершилась; это не валидный результат сравнения моделей.

Две зависшие CLI-команды сборки и скачивания остановлены. Docker reset/prune,
удаление данных/моделей/томов и изменение системных настроек не выполнялись.
По просьбе пользователя работа поставлена на паузу. Продолжение — только по новой команде.
