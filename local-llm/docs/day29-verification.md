# День 29 — итог проверки оптимизации локальной LLM

Финальные живые серии выполнены 8 октября 2026; контроль UI, экспорта и документации завершён
9 октября 2026 (Europe/Samara). Ветка `ai-challenge-day-29`, основа — день 27.
Задание реализовано: настройка temperature / output cap / context, специализированный task prompt,
подключаемый skill, сравнение Qwen3 4B Q4_K_M и FP16. DeepSeek Pro — дополнительный reference.
RAG и книги в этих экспериментах не используются.

## Соответствие заданию

| Требование | Реализация и доказательство |
| --- | --- |
| Настроить параметры под задачу | UI и зафиксированные baseline/candidate; отдельные calibration-серии temperature, context, output cap |
| Попробовать квантование | Одна архитектура Qwen3 4B, Q4_K_M и F16, одинаковые входы/инструкции/параметры, отдельный прогрев |
| Изменить prompt-шаблон | `incident-card-v3`: общий контракт, baseline/specialized; `incident-triage` v2 подключается отдельно |
| Сравнить качество | Строгая схема + пять эталонных полей; смысл summary дополнительно просмотрен вручную |
| Сравнить скорость и ресурсы | HTTP latency, runtime/load time, tokens/s, sampled model allocation; границы измерения явно обозначены |
| Сохранить и показать результаты | SQLite, 29 сохранённых экспериментов, сравнение рядом, вывод пользователя и MD без повторной генерации |

Это оптимизация извлечения фактов из синтетических технических обращений в шесть полей JSON,
а не обещание идеального универсального ассистента. Ошибки модели сохраняются и отображаются.

Покрыты строгий JSON/дубли/хвостовой текст, схема отдельно от точности полей, вход и allowlist,

## Методика и зафиксированный кандидат

Машина: RTX 4080 SUPER, 16 GiB VRAM, около 32 GiB RAM. Ollama 0.35.1.
Каждый случай получает только SYSTEM/USER, без истории, RAG или эталона.
10 calibration-случаев используются для настройки, 10 holdout — для итоговой проверки.
После holdout инструкции не менялись. Окно 4096 оказалось недостаточным для h10 (4249 токенов);
увеличение до 6144 устранило ошибку объёма входа, а не подменило эталон.

Кандидат: SPECIALIZED + skill v2, temperature **0.7**, context **6144**, output cap **512**,
thinking false, top_p 0.8, top_k 20, seed 42. Baseline: BASELINE без skill, 8192/1024,
те же температура и sampling. Это совокупная оптимизация, не изолированный эффект одного параметра.

Для precision-сравнения у Q4 и FP16 совпали все inputs, prompt SHA256, skill и параметры.
Обе модели прогреты отдельным c01 до измеряемых 30 вызовов. Во время этих серий не выполнялись
скачивания моделей или сборки. В памяти разрешена одна локальная модель и один запрос.
Три повтора фиксированного seed показывают воспроизводимость исполнения, не независимую случайную выборку.

### Вывод и ограничения

На этом наборе специализация улучшила Q4 с 6/30 до 27/30 точных карточек. Прогретая Q4 была
примерно вдвое быстрее FP16 по медиане полного времени и использовала около 40% её model allocation.
FP16 не улучшила качество. Это вывод для конкретной задачи и машины, не универсальный рейтинг.

Ошибки не скрыты:

- **h06, обе локальные версии:** игнорируют последнее уточнение про 5%, оставляют P1 вместо P2;
  summary ошибочно говорит про всех пользователей. Каждый из трёх повторов повторил ошибку.
- **h04, FP16:** пять фактов совпали, но `summary=null` нарушает обязательный тип/схему.
  Поэтому 147/150 совпавших полей не означают 27/30 правильных карточек.
- Остальные summary итоговых локальных серий и десять summary DeepSeek просмотрены:
  существенного искажения не найдено. Автоматический evaluator не оценивает смысл summary.
- DeepSeek 10/10 — один контрольный проход, не гарантия безошибочности.

Память — максимум sampled allocation выбранной модели и окна из `/api/ps` (250 мс),
не RSS процесса, не RAM контейнера и не физический пик всей видеокарты. Отсутствующие значения — «—», не ноль.
Медиана полного времени учитывает только COMPLETED и включает HTTP, метаданные, завершение sampler;
качество включает неудачные случаи. Cold load выделен отдельно. Небольшие различия времени не доказывают
статистическую значимость; токенизаторы локальной и облачной модели различаются.
