# День 30: проверка и видео

## Что сдаём

Приватный AI-сервис на домашнем ПК: сеть ZeroTier, HTTP API, Vue-чат, локальная Qwen через Ollama, история SQLite. Без обращения к облачной модели. Базовые ограничения: частота, один активный запрос, окно контекста и размер HTTP-входа.

## Перед записью

1. Ветка `ai-challenge-day-30`, контейнеры healthy. Запуск описан в `day30-zerotier-windows-ios.md`.
2. Оба устройства подтверждены в PRIVATE-сети ZeroTier. `Enable Default Route` выключен: весь интернет через ПК не направляем.
3. VPN listener и Firewall создаются скриптом Enable, привязка только к IP ZeroTier ПК и IP телефона.
4. Сначала убедитесь, что телефон открывает сайт. Пароль приложения введите **до начала записи**, файл .env на видео не показывайте.

## Основное видео — с iPhone

1. Покажите, что Wi-Fi выключен, используется сотовая связь и VPN ZeroTier включён. Не показывайте аккаунт/секреты.
2. Откройте в Safari `http://IP_ПК_ZEROTIER:8583/`. Видно «День 30 · Приватный чат», внизу ограничения сервиса.
3. Создайте чат «День 30 · проверка с телефона», выберите `qwen3:8b`.
4. Настройки: reasoning выключен, температура 0,7, максимум выходных токенов **пустой**. Для обычной работы ограничение 1200 не вводится.
5. Отправьте «Назови столицу Франции одним предложением». Дождитесь реального ответа: Париж.
6. Отправьте «Запомни: мой проект называется Листок, язык Kotlin». Затем «Как называется мой проект и какой язык выбран?». Должны быть Листок и Kotlin.
7. Раскройте «Токены и параметры ответа»: входные/выходные токены, время, число сообщений контекста и причина завершения.
8. Раскройте настройки справа: видно 10 генераций/мин, один активный запрос, окно 8192 токена, отдельный UTF-8 budget 24576 байт. Это два разных ограничения, не приблизительная «конверсия» байтов в токены.
9. Перезагрузите страницу: история сохраняется. Выключите ZeroTier и обновите страницу/запросите историю: новый сетевой запрос не проходит. Уже загруженный HTML может оставаться на экране — это не доказательство доступа. Включите VPN и обновите: чат снова открывается.

## Дополнительная демонстрация ограничений — с ПК

В PowerShell из репозитория:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 'F:\ai-advent-challenge\ai-chat\local-llm\scripts\Verify-Day30.ps1'
```

Тест делает реальные вызовы локальной модели. Выходные лимиты 16/128/512 используются явно **только в тестовых сообщениях**, не меняют настройки приложения.

Скрипт показывает PASS для: закрытой истории без входа, неправильного пароля, успешного входа, памяти, replay без дубликата, большого UTF-8 запроса 422, конкурентного отказа 503 + Retry-After, последовательных ответов, rate limit 429 + Retry-After, чтения после rate limit и отзыва сессии. Чаты проверки остаются в UI, секреты не выводятся. Во время теста не отправляйте другие сообщения, чтобы не вмешиваться в общий лимит владельца.

Точный минутный алгоритм отдельно проверен unit-тестом на монотонных часах. В живом прогоне ранние медленные запросы могут выйти за минутное окно; число дополнительных успешных запросов до 429 зависит от времени, это нормально.

## Перезапуск и сохранение истории

Не во время активной генерации:

```powershell
docker compose --env-file local-llm/.env.day30 -f local-llm/compose.day30.yml restart backend
```

Дождитесь health, обновите страницу, войдите заново. Сессии намеренно аннулированы, история должна остаться. Спросите «Напомни проект и язык» в прежнем чате. Не используйте `down -v`.

## Настоящее переполнение окна

В ходе автоматической проверки был сохранён отдельный чат «День 30 · предел окна Ollama»: диагностический текст требует 15734 токена при окне 8192. Модель не генерирует ответ, USER имеет FAILED и понятную причину, история не удалена. Это отдельная проверка от UTF-8 guard, который даёт 422 ещё до LLM.

Для короткого видео выбирайте свежий обычный чат, а не нагрузочный с сотнями чисел. Полный отчёт не заменяет реальную проверку iPhone: доступ с сотовой сети нужно подтвердить на самом телефоне.
