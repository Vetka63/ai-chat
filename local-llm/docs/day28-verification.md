## Граница задания

Индексация, embedding вопроса и retrieval выполняются локально. Генерация LOCAL — через
локальную Ollama; DEEPSEEK/COMPARE включаются явно. COMPARE готовит один контекст, затем
параллельно запускает независимые генераторы. Нет cloud rewrite/judge/fallback.

**Согласованное отклонение от буквального задания:** используется новый индекс Warhammer,
а не физический индекс Pro Git дней 21–25. Старый RAG-проект не менялся. Если проверяющий
требует именно прежний индекс, эта демонстрация не доказывает его повторное использование.

## Контрольная серия на текущем индексе

`evaluation/day28-cases.json`: десять вопросов, по три повтора, LOCAL/DeepSeek Pro рядом.
Параметры: topK = 5, threshold = 0.35, contextCharacters7000, temperature = 0, thinking false,
явный тестовый output cap = 512. В обычном UI cap по умолчанию не задаётся.
Во время этой серии скачивания и сборки не выполнялись.

Результаты: ignored `artifacts/day28-restored-20261009`, также доступны в UI.
Все **30 экспериментов / 60 ответов завершились**. Для каждого вопроса hash общего контекста
сохранился во всех трёх повторах; интервалы работы LOCAL/DEEPSEEK перекрываются во всех 30 парах.
Это параллельные провайдеры после одного retrieval, не параллельная загрузка двух локальных моделей.

| Метрика | Qwen3 8B | DeepSeek Pro |
| --- | --- | --- |
| Завершённые ответы | 30/30 | 30/30 |
| Существующие ID ссылок | 30/30 | 30/30 |
| Ожидаемые слова (только эвристика) | 30/30 | 30/30 |
| Медиана времени провайдера | 1011 мс | 1882 мс |
| Медиана повторов 2–3 | 904,5 мс | 1729 мс |
| Среднее время всех вызовов | 2275 мс | 1994 мс |

Время провайдера включает HTTP и локальную загрузку модели, но не общий retrieval;
полное время эксперимента показано отдельно. Среднее и медиана расходятся из-за холодных
перезагрузок после embedding. В памяти Ollama держится одна модель: безопасность памяти
важнее удержания всех весов одновременно. Кешируются query-вектора, **не ответы**.
Цифры не являются универсальным рейтингом; cloud зависит от сети, токенизаторы различаются.

## Смысловое ревью и честные ограничения

Просмотрены все варианты 60 ответов и подтверждающие фрагменты. Основные ожидаемые факты
найдены обеими моделями: восемь имён, пилот «Валькирии», принадлежность флоту, Чёрная Ярость,
Пресекатель Песен, ветер в шахтах/туннелях, антарийский полк, Аллектий и должность Рагуила.
Однако нельзя назвать всю серию безошибочной:

- **faith-chaplain, LOCAL, повтор 1**, `d7d3e8a8-4cd5-416f-be24-856c4b38a46e`:
  должность названа правильно, но добавлено неверное «руководит испытанием».
  S1 прямо говорит, что Рагуилу не позволили руководить и даже присутствовать.
  Другие два повтора не добавили это утверждение. Ошибка сохранена, не подправлялась backend.
- При LOCAL redeemer-role ссылка S2 подтверждает долг, тогда как прямое упоминание
  Чёрной Ярости находится в S1. Это ещё одна причина не путать правильный ID с точной атрибуцией
  каждой части утверждения. Глобальный предоставленный контекст содержит нужный факт.
- У DeepSeek не обнаружено аналогичного существенного фактического противоречия на этих
  десяти вопросах; это ограниченное ревью, не автоматический семантический сертификат.
- На первом вопросе Qwen сообщает восемь имён, DeepSeek дополнительно даёт расположение 4/4;
  вопросы не требуют буквального совпадения текста. Три повтора недостаточны для универсальной
  оценки стабильности; даже temperature = 0 не обещает одинаковую формулировку.

Вывод: локальный RAG действительно находит и использует предоставленный текст. На прогретых
повторах Qwen быстрее в этой серии, но может добавлять неподтверждённые детали. DeepSeek оказался
аккуратнее на найденном контрпримере. Ни COMPLETED, ни VALID не означают доказанную истинность.
Мини-набор в основном содержит явные названия рассказов и не покрывает все сложные виды вопросов.

## Полностью локальное доказательство

Реально запущен `start-day28.ps1 -Offline`:

- backend и Ollama подключены только к `ai-chat-local-llm_offline`, network.Internal=true;
- cloud flagfalse, API-ключ пуст; внешний `curl https://example.com` из backend дал DNS error6;
- Nginx имеет обычную сеть только для localhost-входа и internal-сеть для reverse proxy;
- новый вопрос `9e9be1c4-1e7b-4ae2-88b7-3516ae579471` получил embedding **без cache hit** и
  правильный локальный ответ: восемь имён, четыре на каждой стороне. Индекс не перестраивался;
- новый COMPARE отвергнут HTTP400 без нового эксперимента. Старый UUID вернул прежний объект
  даже при отключённом облаке: чтение/повтор receipt не вызывает модель;
- просмотр и сохранение результата работают через UI/proxy8483. Прямой порт 8482 в этом профиле
  на Windows не является надёжным способом доступа.

Первый offline запуск после смены контейнеров был холодным: retrieval29 с, загрузка Qwen26 с,
общее время 77 с. Этот результат не смешан с benchmark таблицей выше; полной причины замедления
из одного запуска не устанавливаем. Проверено 100% GPU, а не облачная/CPU подмена.
