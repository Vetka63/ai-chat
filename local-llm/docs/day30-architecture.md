# День 30: локальная LLM как приватный сервис

Ветка `ai-challenge-day-30` ответвлена от `ai-challenge-day-27`. Модель остаётся на домашнем Windows-ПК с GPU. VPS и публичный IP не нужны. Старые чаты и результаты дней 26–29 не копируются и не удаляются.

## Путь запроса

Safari на iPhone → зашифрованная PRIVATE-сеть ZeroTier → TCP listener только на IPv4 интерфейса ZeroTier → Windows portproxy → Nginx/Vue на `127.0.0.1:8583` → Kotlin/Spring Boot → Ollama `/api/chat` → Qwen на GPU.

Nginx доставляет `/api/v1` backend внутри Docker. Сам backend опубликован только на loopback `127.0.0.1:8582` для диагностики. Ollama вообще не имеет опубликованного host-порта в Compose дня 30. HTTP-пакеты на участке телефон–ПК защищает ZeroTier; это НЕ публичный HTTPS-сайт. На localhost и внутри Docker используется HTTP. Без ZeroTier и VPN listener приложение доступно лишь с ПК.

Сеть ZeroTier разрешает только подтверждённые устройства. Windows-правило разрешает TCP 8583 только с указанного IPv4 iPhone на ZeroTier-интерфейс. Не создаются listener `0.0.0.0`, проброс WAN-портов или публичный reverse tunnel. Локальный адрес телефона фиксируйте в Central; при его изменении доступ перенастраивается явно.

## Дополнительный вход в приложение

`PrivateAccessFilter` проверяет все backend API, включая историю, runtime, лабораторные вызовы и отчёты. Для приватного Compose защита всегда включена. `PrivateProperties.validate` запрещает запуск с пустым/коротким секретом. Вход: `POST /api/v1/private/session`; пароль генерируется в `.env.day30`, файл игнорируется Git и Docker build context.

`SessionStore` выдаёт случайную 256-битную cookie, сохраняет лишь SHA-256 токена в памяти. Cookie: HttpOnly, SameSite=Strict, срок 8 часов. Secure не включён, поскольку выбран HTTP внутри VPN, а не HTTPS. Для публичного размещения эта конфигурация НЕ подходит. Перезапуск backend завершает сессии, но сохраняет SQLite. Выход отзывает текущую сессию. Максимум 16 сессий, старейшие вытесняются.

Запросы изменений требуют `X-Day30-Request: 1`; браузерный Origin должен точно входить в разрешённые адреса. CORS не включён. Клиентские identity/X-Forwarded-For заголовки не принимаются за доверенную идентичность. Один пароль означает одного владельца: отдельной многопользовательской модели прав на чаты здесь нет.

Nginx ограничивает body до 64 КиБ, запрещает iframe и сторонние scripts/connect через CSP. Ответ модели выводится Vue как текст, не исполняемый HTML. Неавторизованный клиент не получает историю. После HTTP 401 UI скрывает чат и предлагает войти.

## Серверные ограничения

- `MinuteLimiter`: скользящие 60 секунд на монотонных часах. 10 новых генераций в минуту на ВСЕ сессии владельца вместе; смена cookie/IP не сбрасывает лимит. Явный retry расходует quota. Replay уже сохранённого requestId не расходует quota и не вызывает LLM.
- Лимит входа: 5 попыток/мин, включая успешные. HTTP 429 + Retry-After, без автоматического повтора. Все лимиты в памяти: перезапуск процесса сбрасывает их. Это домашний single-instance сервис, не распределённый rate limiter.
- `GenerationGate`: один активный запрос; второй получает HTTP 503 + Retry-After. Очереди нет. Лабораторные запросы и чаты разделяют один gate и quota.
- `ServiceLimits.context`: текст текущего запроса + передаваемых успешных реплик + системной инструкции, максимум 24576 байт UTF-8. Это размер текста, НЕ точный подсчёт токенов и не формула перевода символов в токены. Превышение: HTTP 422 до сохранения хода и вызова модели. Предыдущая история остаётся без изменений; UI возвращает текст в поле ввода.
- В Ollama передаётся серверный `num_ctx=8192`, `truncate=false`, `shift=false`. Настоящее переполнение токенов проверяет tokenizer/runtime Ollama; ошибка сохраняется в пользовательском ходе и показывается в UI. Старые сообщения не вырезаются. Во время генерации исчерпание окна/явного лимита отмечается TRUNCATED, не COMPLETED.
- `prompt_eval_count`/`eval_count` из ответа Ollama — фактические токены. `maxOutputTokens=null` не добавляет `num_predict`; скрытого приложения-лимита 1200 нет. Пользователь может задать явный предел выхода.
- На GPU: одна загруженная модель, один параллельный runtime-запрос; RAM-cache весов выключен. Timeout backend 300 с, reverse proxy 360 с. Cloud fallback отсутствует, `OLLAMA_NO_CLOUD=1`.

## История и идемпотентность

`ChatController` → `ChatService` → `ChatRepository` → `day30.sqlite`. У каждой реплики UUID requestId, нормализованный на сервере. Пользовательский ход записывается до runtime, ответ/ошибка — после. Перезапуск восстанавливает незавершённый ход как FAILED без скрытого запуска. Контекст берётся только из выбранного чата. Неопределённая потеря HTTP-ответа сверяется с сохранённым чатом; повтор использует тот же ID. Определённые 422/429/503 не изображаются потерянными ответами.

На HTTP-адресе iPhone `crypto.randomUUID` может отсутствовать: UI формирует UUIDv4 через `crypto.getRandomValues`, без слабого Math.random.

## Развёртывание

`compose.day30.yml`: отдельный проект `ai-chat-day30`, отдельный volume `ai-chat-day30_day30-data`. Только read/use существующего volume весов `ai-chat-local-llm_local-models`; образы/историю прошлых дней не удаляем. Не запускайте одновременно несколько Ollama с общей библиотекой/GPU для генерации.

`Initialize-Day30.ps1`: одноразовый секретный env-файл, без вывода пароля. `Start-Day30.ps1`: проверка Docker/volume/20 ГБ свободного C:, healthcheck, запуск. `Enable-Day30ZeroTier.ps1`: проверка PRIVATE/OK сети и IP-интерфейса, точный Origin, перезапуск backend, узкий Firewall/portproxy. `Disable-Day30ZeroTier.ps1`: удаляет только созданные им listener/правило; данные остаются.

Для работы 24/7 ПК должен быть включён и не спать, ZeroTier/Docker должны работать. `restart: unless-stopped` восстанавливает контейнеры при рестарте Docker, но не гарантирует запуск Docker Desktop до входа в Windows. Автологин, отключение сна и широкие настройки Firewall автоматически не меняются.

Схема: `diagrams/day30-private-service.html`. Русский текст компонентов; фиксированный Viewer UI Archify остаётся английским.
