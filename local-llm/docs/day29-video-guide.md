# День 29 — проверка через UI и запись видео

Актуально на 9 октября 2026. Папка `F:\ai-advent-challenge\ai-chat\local-llm`, ветка `ai-challenge-day-29`.
Все основные результаты уже сохранены на backend. Для видео их можно открыть без повторных
LLM-вызовов и расходов DeepSeek. Они доступны из любого браузера, не только из браузера проверки.

## 1. Подготовить приложение

Если http://localhost:8483 уже открывается, ничего перезапускать не нужно.
Иначе включите Docker Desktop и выполните в PowerShell:

```powershell
cd F:\ai-advent-challenge\ai-chat\local-llm
./scripts/start-day29.ps1 -Model qwen3:4b-q4_K_M -Cloud
```

`-Build` добавляйте после изменения кода. Для только локальных новых запросов уберите `-Cloud`.
Ключ хранится в корневом `.env`: не показывайте файл, environment контейнера или ключ на видео.
Скрипт проверяет свободное место на диске данных Docker (минимум 20 GiB), готовность runtime/backend
и скачивает только недостающие веса. Не запускайте смену модели во время генерации.

Откройте [лабораторию](http://localhost:8483/#optimization).
Слева — сохранённые эксперименты с датой и коротким UUID; справа — настройки **нового** запуска.
Для параметров **сохранённого** результата используйте «Сохранённая конфигурация» под ответами.
Если локальный runtime после простоя выгрузил модель, это нормально: следующий LOCAL-запрос загрузит её.

## 2. Показать «до» и «после» оптимизации

1. Откройте [Q4 после оптимизации](http://localhost:8483/#optimization/56d2d43e-2ca7-4c54-b209-6fef16c0380d).
   Это метка **56d2d43e** в левом списке, 30/30 завершённых вызовов.
2. Прокрутите основную колонку ниже формы до заголовка сохранённой модели и таблицы качества.
3. В «Сравнить с сохранённым экспериментом» выберите Q4 BASELINE с меткой **f9fb5df2**.
4. На экране должны быть две колонки:

   | Метрика | После, 56d2d43e | До, f9fb5df2 |
   | --- | --- | --- |
   | Точные карточки | 27/30 | 6/30 |
   | Верные поля | 147/150 | 123/150 |
   | Валидная схема | 30/30 | 30/30 |
   | Медиана успешных вызовов | 384 мс | 515 мс |
   | Sampled max VRAM | 3,44 GiB | 3,72 GiB |

5. Предупреждения о разных инструкциях и настройках **ожидаемы**: это общий эффект оптимизации,
   а не чистое сравнение квантования. Не скрывайте их.
6. Выберите вкладку **h01 · 1**. В ответах видно, что неизвестная причина должна быть `null`,
   а базовый профиль может записать «неизвестна» строкой. Раскройте «Входное обращение».
7. Выберите **h06 · 1**. После уточнения затронуты лишь 5%, но локальная модель оставила P1.
   UI показывает ошибку: это демонстрация честной оценки, не поломка приложения.
8. Раскройте «Сохранённая конфигурация»: baseline 8192/1024 без skill;
   candidate 6144/512, SPECIALIZED + skill, temperature 0.7, Thinking выключен.
9. Покажите сохранённый «Мой вывод». Нажмите «Скачать MD».
   Обновление страницы сохраняет эксперимент и вывод; выбранное сравнение можно выбрать заново.

**Не нажимайте «Запустить эксперимент» при просмотре:** это создаст новый прогон, а не откроет прежний.
Данные результатов не редактируются; редактировать можно только собственный вывод.

## 3. Показать квантование: Q4 и FP16

Для показа готового сравнения не нужно переключать активную модель или снова скачивать веса.

1. Откройте [FP16](http://localhost:8483/#optimization/772d855b-1eb7-48c3-94e7-65f6cb317fb3), метка **772d855b**.
2. В сравнении выберите **78e3cdb8** — прогретый Q4 precision reference, SPECIALIZED.
   Не используйте baseline или однопроходный provider reference для этого шага.
3. Должно быть **без предупреждений о смешении параметров**:
   одинаковые десять входов × три повтора, инструкции, skill и параметры.
4. Покажите таблицу:

   | Метрика | FP16 | Q4 |
   | --- | --- | --- |
   | Точные карточки | 24/30 | 27/30 |
   | Валидная схема | 27/30 | 30/30 |
   | Медиана времени (округлено в UI) | 736 мс | 354 мс |
   | Sampled max VRAM | 8,49 GiB | 3,44 GiB |

5. Выберите **h02 · 1**: в деталях видны время, токены/с, GPU и фактическое окно 6144.
   Сравните скорость генерации; ориентиры медиан серий — около 74 против 168 токенов/с.
6. Выберите **h04 · 1**: FP16 вернула `summary=null`, UI отмечает нарушение схемы,
   хотя пять проверяемых фактов совпали. Покажите, почему это не правильная карточка.
7. Раскройте «Сохранённая конфигурация» и покажите одинаковую Qwen3 4B, F16 / Q4_K_M и разные digest.
8. Покажите сохранённый вывод и скачайте MD.

FP16 — float16 без низкобитного integer-квантования, не FP32.
Серии выполнены по очереди после отдельного прогрева, не одновременно на GPU.
Справа может быть активная Q4, хотя открытый результат получен FP16: это корректно,
панель относится к будущему запуску, результат — к своей сохранённой модели.
Allocation — не RSS и не полный пик всей видеокарты; соответствующая подпись есть под ответами.

## 4. Дополнительно показать DeepSeek

1. Откройте [DeepSeek Pro](http://localhost:8483/#optimization/006da38d-4762-4a5f-9013-45f7129794df), **006da38d**.
2. Для сравнения выберите Q4 **b632686c**: те же десять holdout-случаев, один повтор.
3. Покажите **10/10 против 9/10** точных карточек, 50/50 против 49/50 полей.
4. Выберите **h06 · 1**: DeepSeek учитывает исправление про 5%, а Q4 ошибается.
5. Покажите предупреждение о разных провайдерах. В облаке RAM/VRAM неизвестны («—»).
   Локальные context/top_k/seed к DeepSeek не применяются; точные параметры доступны в конфигурации/MD.
6. Покажите вывод пользователя. Это дополнительный reference, не тест квантования.

Открытие этого сохранённого результата не отправляет новые данные в DeepSeek.
Платная передача происходит только при явном запуске нового эксперимента с провайдером DeepSeek API.

## 5. Показать, зачем нужны разумные ограничения

Достаточно одного-двух отрицательных примеров; все они уже сохранены.
Перед каждым выберите «Без сравнения», чтобы не смешивать разные наборы.

- [Обрезанный JSON](http://localhost:8483/#optimization/4d4aecf1-6dfe-4405-b190-9462b06c7086), **4d4aecf1**:
  h07, cap64. PARTIAL / TRUNCATED, 64 выходных токена, незакрытый JSON. Backend не чинит его за модель.
- [Thinking исчерпал бюджет](http://localhost:8483/#optimization/aab8c69b-7c8b-4407-ae32-48cd5d865f33), **aab8c69b**:
  пустой итоговый ответ, но видны предупреждение и 64 выходных токена.
  Раскройте «Thinking модели до итогового ответа», скачайте MD: reasoning и usage сохранены.
- [Малое окно контекста](http://localhost:8483/#optimization/01a3960d-7a2c-4f0e-912c-c9861fb34a33), **01a3960d**:
  h10 требует 4249 токенов при окне 4096, поэтому FAILED. Вход не обрезается и облако не подменяет модель.
- [После ошибки слот свободен](http://localhost:8483/#optimization/4727d12d-afb3-472d-ab87-0d0cf8d7268e), **4727d12d**:
  обычный c02 завершился, 5/5 полей.

Короткие c01/h05 помещаются в cap64; они не подходят для демонстрации обрезания.
COMPLETED означает завершение генерации, не правильность её содержания.

## 7. Самостоятельный новый прогон (не обязателен для готового видео)

1. Нажмите «+ Новый эксперимент», затем «Базовый профиль».
2. Выберите «Для настройки · 10» → «Выбрать весь набор» → один повтор.
3. Запустите, дождитесь результата; нажмите «+ Новый эксперимент» → «Кандидат оптимизации».
4. Выберите тот же набор и число повторов, запустите, выберите первый результат для сравнения.
5. Для изолированного опыта меняйте только один параметр: температуру, окно, cap или skill.
   Не подбирайте инструкции по итоговому holdout и не удаляйте неудачные ответы.
6. Для свежего precision-сравнения сохраните настройки, прогрейте каждую модель одним отдельным
   случаем, затем запускайте одинаковый набор. Модель переключайте только после завершения:

```powershell
./scripts/start-day29.ps1 -Model qwen3:4b-fp16 -Cloud
# После FP16-прогона вернуть Q4 для обычного использования:
./scripts/start-day29.ps1 -Model qwen3:4b-q4_K_M -Cloud
```

CLI-прогоны сохраняют квитанцию и полный result.json в ignored artifacts:

```powershell
./scripts/verify-day29.ps1 -Provider LOCAL -PromptProfile BASELINE -Split calibration -ContextSize 6144 -MaxTokens 512
./scripts/verify-day29.ps1 -Provider LOCAL -PromptProfile SPECIALIZED -Skill -Split calibration -ContextSize 6144 -MaxTokens 512
```

Одинаковый `-OutputDirectory` и настройки читают прежний UUID без новой генерации;
для нового прогона нужна новая папка. Повторяемость seed между разными runtime/precision не гарантирована.

Остановить только приложение, не удаляя данные:

```powershell
docker compose --env-file ../.env -f compose.yml -f compose.gpu.yml stop
```
