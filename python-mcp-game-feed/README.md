# Game Feed MCP · День 18

Отдельный Python-проект рядом с агентным бэкендом. `server.py` объявляет MCP-инструменты
`create_watch`, `get_watch`, `cancel_watch`, `delete_watch`, `list_reports` и `collect_games`.
`worker.py` периодически проверяет наступившие подписки и вызывает **`collect_games`
через MCP Client**, а не напрямую. MCP-сервер берёт игру из сменного источника
`GameSource` (сейчас `GeneratedGameSource`), добавляет её в SQLite и создаёт
сводку. IGDB пока не подключён.

Сервер и worker запускаются как **два контейнера одного образа** и используют
общий постоянный том `game-feed-data`. Запускайте только один экземпляр worker:
этот учебный вариант не является распределённой очередью. SQLite содержит
`watches`, `games`, `runs`, `reports`; для каждой подписки остаются три последних
отчёта. `runs` позволяет видеть историю запусков, а уникальный ключ
`(watch_id, scheduled_for)` защищает от повторной записи после сетевого сбоя.
При ошибке MCP worker возвращает запуск в очередь. Расписание и отчёты переживают
перезапуск контейнеров.

Граница будущего IGDB: реализовать `GameSource.fetch(known_ids)` и выбрать новый
источник в `server.py`. Остальные слои (worker, MCP-контракт, агент и UI) менять
не нужно. Для боевой эксплуатации дополнительно понадобятся аутентификация,
лимиты запросов, наблюдаемость и полноценная очередь для нескольких worker.

Проверка из корня репозитория:

```powershell
docker compose up -d --build python-mcp-game-feed game-feed-worker agents-backend agents-client
docker compose ps
```

Клиент: <http://localhost:8083>. Выберите агента «Игровые сводки», создайте
отдельный чат, задайте интервал 1 минута и нажмите «Запустить». Первый сбор
запланирован сразу; новые сводки будут появляться каждые 60 секунд.
В UI видны последние три, время следующего запуска и кнопка остановки.
Ключ DeepSeek для этого сценария не требуется: отчёт формируется детерминированно.
