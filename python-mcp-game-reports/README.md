# Три MCP-инструмента игровых отчётов · День 19-v2

Один самостоятельный HTTP MCP-сервер объявляет три инструмента в tools/list:

1. search_games(query) запрашивает игры у Java mock-games-server по HTTP и
   возвращает SearchResult {query, games}.
2. summarize_games(search_result) принимает **полный результат первого
   инструмента** и возвращает SummaryResult {query, game_count, markdown}.
   Текст формируется воспроизводимо без дополнительного LLM-вызова.
3. save_report(summary_result, operation_id) принимает **полный результат
   второго инструмента** и сохраняет Markdown в томе game-report-data.
   Возвращает имя файла, ID, число игр и содержимое для скачивания в UI.

Сервер не запускает всю цепочку одной функцией. Три отдельных tools/call делает
GameReportsAgent: сначала модель выбирает поиск по явной просьбе пользователя,
затем агент из результата поиска формирует аргумент summarize_games и из
результата обработки — аргумент save_report. Порядок и типы проверяются.
При ошибке поиска или обработки файл не создаётся.

operation_id — UUID, который агент вычисляет из чата и номера сообщения.
Повтор сохранения возвращает тот же файл; пользовательский путь к файлу
не принимается. MCP доступен по Streamable HTTP на /mcp. В параллельном
Compose-проекте day19-v2 локальный host-порт — 8188; контейнеры общаются
по внутреннему адресу python-mcp-game-reports:8080.

Тесты в tests/test_pipeline.py проверяют список из трёх tools, схему входа,
точную передачу структурированных результатов, идемпотентность и ошибки.
