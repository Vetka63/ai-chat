# selection: второй этап после cosine search

`CandidateSelector` отделяет поиск от политики отбора. `SimilarityCandidateSelector` принимает уже ранжированные SearchHit, final top-K и nullable threshold. Он не вызывает LLM и не меняет score.

1. Проверяет конечность и диапазон параметров.
2. Для каждого кандидата: score меньше threshold → BELOW_THRESHOLD.
3. Подходящий кандидат при уже заполненном final K → TOP_K_LIMIT.
4. Иначе → SELECTED. Порядок исходного ranking сохраняется.

При threshold=null работают только final top-K и журнал; это контрольные режимы без фильтра. Равенство порогу считается допустимым. Например, при final K=2 и threshold=0,65 оценки 0,80 / 0,65 / 0,64 / 0,60 оставляют первые два; последние два исключены по порогу.

`CandidateSelection` хранит selected и решения для всех исходных кандидатов. Бюджет контекста здесь не применяется: он принадлежит PromptAssembler. Поэтому UI может различить «не прошёл порог», «не попал в final K» и «отобран, но не поместился».

Это similarity-фильтр, не cross-encoder reranker. Порог не универсален и не означает вероятность правильного ответа. Будущий reranker может реализовать этот порт с другой политикой, но потребует собственной прозрачной оценки и модели/версии в контракте эксперимента.
