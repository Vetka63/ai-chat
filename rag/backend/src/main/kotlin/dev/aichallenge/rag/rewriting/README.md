# rewriting: запрос для поиска, не ответ пользователю

Порт `QueryRewriter` возвращает RewriteTrace. Адаптер `LlmQueryRewriter` использует существующий LlmClient и CostEstimator; отдельный SDK или новый ключ не нужен.

Промпт просит поисковую формулировку по русскому Pro Git: сохранить смысл, команды, имена и отрицания; не отвечать, не добавлять факты и не превращать постороннюю тему в Git. Ввод сериализуется как данные JSON. Ответ в JSON mode должен содержать ровно `query`, непустую строку до 1000 символов. Дополнительные поля, массив, неправильный тип, пустой текст или finish_reason не stop отклоняются с `invalid_rewrite`.

Технический output budget 512 не ограничивает пользовательский ответ. Формат JSON проверяется, но это не семантическая гарантия корректной переформулировки. Поэтому UI показывает «Было / Стало» и исходный ответ провайдера (только content), а генератор получает исходный вопрос.

RewriteTrace содержит query, фактическую модель, finish reason, время, API usage, оценку стоимости, точные публичные messages и JSON content. Ключ и Authorization отсутствуют. Не сохраняется chain-of-thought. Сетевой или форматный сбой не запускает retry. ExperimentService сохраняет ошибки rewrite отдельно и продолжает только режимы, не требующие его.

Официальный контракт: [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/). JSON mode помогает соблюдать структуру, но пустой/обрезанный ответ всё равно надо обрабатывать. Замена провайдера выполняется через LlmClient, замена подхода rewrite — через QueryRewriter.
