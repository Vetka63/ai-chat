# Память задачи и подготовка вопроса

Этот домен хранит не знания о Git, а то, что пользователь сообщил о своей задаче. Например, «сохранить изменения», «коммит опубликован», «не использовать force push», «под основной веткой понимаем main».

## Слои памяти

| Слой | Пример | Что не нужно сохранять |
| --- | --- | --- |
| GOAL | Исправить ошибочный коммит и сохранить правки | Каждый локальный вопрос вместо общей цели |
| CLARIFICATIONS | Коммит уже опубликован | Гипотетическое «а если он опубликован?» как свершившийся факт |
| CONSTRAINTS | Общую историю переписывать нельзя | Временное состояние коммита как неизменяемый запрет |
| TERMS | Рабочая ветка называется feature-login | Команды и советы из ответа модели |

## Классы и алгоритм

`DialoguePreparer` — заменяемый порт. `LlmDialoguePreparer` вызывает существующий LlmClient в JSON mode, без собственного output cap, с отдельным system prompt. В его входе current question, validated memory и ограниченный recent dialogue; книги здесь нет. Он не отвечает пользователю и не выполняет инструментов.

Ожидаемый JSON содержит `query`, `updates` и `removals`. Query раскрывает местоимения для retrieval, но не заменяет original question в истории. Update задаёт layer/key/value/quote. SourceTurnId всегда назначается сервером, модель не может сослаться на произвольный чат или assistant response.

`MemoryPatchValidator` проверяет finish_reason, размер, точную структуру, bounded fields, допустимый enum, одинаковые ключи и наличие каждой quote в текущем вопросе. При ошибке весь patch отвергается. Сервер применяет upsert по layer/key, поэтому новое значение того же факта заменяет старое, а не дублируется. Удалять можно только существующий ключ с цитатой текущего сообщения. Не более 20 изменений за turn и 12 записей каждого слоя (GOAL одна); переполнение — явная ошибка, не тайное вытеснение памяти.

После первого GOAL изменения этого слоя без явного префикса «Новая цель:», «Измени цель:» или «Моя новая цель:» не применяются. Query и остальные корректные изменения продолжают работать. Это серверная защита от goal drift, найденного в первой живой проверке. Исходное предложение модели остаётся в rawJson, список changes содержит только применённые изменения. Определение смысла ограничения/уточнения остаётся задачей LLM, поэтому пользователь видит память и её происхождение в UI.

## Пример

User: «Нельзя терять изменения. Что делает reset --soft?»

```json
{"query":"Что делает git reset --soft с изменениями?","updates":[{"layer":"CONSTRAINTS","key":"preserve_changes","value":"Не терять изменения","quote":"Нельзя терять изменения."}],"removals":[]}
```

Сервер добавляет sourceTurnId текущего user message. На следующем шаге «А что станет с индексом?» query может стать «Что делает reset --soft с индексом Git?», а оба массива patch быть пустыми. Память при этом сохраняется полностью; это не summary диалога.

Точное совпадение quote доказывает происхождение строки, но не семантическую эквивалентность value. Prompt запрещает гипотезы и чужие инструкции; это не математическая гарантия защиты от всех prompt injection. При критичных правилах потребуется отдельное подтверждение пользователя или специализированная validation policy.
