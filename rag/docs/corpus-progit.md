# Русская Pro Git как корпус RAG

Основной корпус — неизменённые текстовые секции глав 2, 3, 7 и 10 русского перевода второго издания Pro Git. Исходники скачаны из [официального репозитория перевода](https://github.com/progit/progit2-ru) по commit `bef0ce52475e44b8c9d66d7ff8c6a03b37758a03`. [Книга онлайн](https://git-scm.com/book/ru/v2) позволяет сверить содержание, но runtime не обращается к ней на каждом поиске.

## Состав и происхождение

В snapshot 36 файлов sections и один вспомогательный Ruby-пример из того же commit. Главы охватывают запись изменений, remote, ветвление/слияние, reset, инструменты и внутреннюю модель Git. `subtree-merges.asc` индексируется отдельным документом: parent include превращается в явную ссылку, а не дубликат текста. Ruby-пример разворачивается в code block credentials и проверяется по SHA из manifest.resources. Изображения и произвольный AsciiDoc include graph не включены: ответы по рисункам пока проверить нельзя. SourceLine обозначает начальную строку блока подготовленного входа; после include expansion она не является точным оригинальным диапазоном.

`manifest.json` закрепляет revision, checksum скачанного ZIP и каждого исходника, список глав, repository URL, attribution и CC BY-NC-SA 3.0. Файл LICENSE.asc сохраняется рядом. У нормализованного текста сохраняется отдельный hash: он не равен hash исходного AsciiDoc.

Книга написана Scott Chacon и Ben Straub; русский текст — перевод участников проекта. [README перевода](https://github.com/progit/progit2-ru) предупреждает об отсутствии профессиональной редактуры. При спорных эталонных ответах сверяем именно сохранённый русский текст, а не приписываем ему формулировки другой версии.

## Подготовка и повторение

Скрипт prepare-corpus.ps1 читает ZIP как набор entries, извлекает только допустимые текстовые пути и не выполняет чужой код. Проверка не допускает выход пути за целевой каталог и неожиданные большие entries. При существующем snapshot скрипт не скачивает latest и не перезаписывает файлы, а проверяет revision и hashes.

При намеренном обновлении книги нужно подготовить новый corpus profile/snapshot, заново проверить fixtures и построить новые индексы. Нельзя заменить тексты под старым snapshot ID.

## Объём

API corpus и UI показывают число слов/символов/разделов по каноническому уникальному тексту. Формула условного количества страниц — words / 400. Это измеримая оценка эквивалента текста, а не фактическая страница печатного PDF. Повторения overlap не увеличивают объём материала для задания.

## Контрольные вопросы

Готовой QASPER-разметки в книге нет. День 21 использует небольшие ручные поисковые проверки; день 22 получит десять проверенных QA с ожидаемыми фактами и evidence ranges. Этот корпус подходит для учебных требований, но результаты не объявляются воспроизведением научного бенчмарка QASPER.

DeepSeek может уже знать Git, поэтому правильный no-RAG ответ допустим. Отдельно измеряем извлечение источников и подтверждение утверждений цитатами. Вопросы о конкретных примерах книги полезнее для сравнения, чем только «что такое Git».

Hugging Face datasets не обязательны для запуска. Если добавим SberQuAD/MIRACL/Vikhr проверки, они будут отдельными corpus/evaluation profiles с собственной лицензией и manifest. Синтетический ответ из датасета нельзя объявить проверенным эталоном без сверки с источником.
