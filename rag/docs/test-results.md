# День 21: результаты проверки и сравнение стратегий

Итоговая проверка: **3 октября 2026 года**, Windows + Docker Desktop, ветка `ai-challenge-day-21`. Это первый день RAG-недели — индексация документов, не генерация ответов. DeepSeek не вызывался; эмбеддинги вычислены локально через Ollama.

## Выполнение задания

| Требование | Реализовано и проверено |
| --- | --- |
| Не меньше 20–30 страниц текста | 36 документов русского перевода Pro Git, 56 957 слов; 142,39 условной страницы при 400 словах на страницу |
| Разбиение документов на чанки | FIXED — фиксированные окна; STRUCTURAL — окна внутри разделов с предпочтением границ блоков |
| Генерация эмбеддингов | Настоящие 1024-мерные векторы `qwen3-embedding:0.6b`, не mock и не приблизительная имитация |
| Локальный индекс | SQLite: канонические snapshots, индексы, тексты чанков, метаданные и Float32-векторы |
| Метаданные | source, title, section, chunkId, documentId, исходные диапазоны и SHA256 текста |
| Сравнение двух стратегий | Таблица метрик, диагностический поиск по обоим индексам, скачивание MD/JSON |
| Сохранение результатов | После перезапуска backend сохранились те же index IDs и порядок chunk IDs для повторного поиска |

Условные страницы — оценка объёма текста, а не количество страниц печатного издания. В корпусе 193 раздела и 417 329 символов UTF-16 нормализованного текста. Исходники, revision, лицензия и преобразования описаны в [документации корпуса](corpus-progit.md).

## Условия сравнения

Обе стратегии построены на одном snapshot, с одинаковыми `maxCharacters=3000` и `overlapCharacters=300`. Размеры здесь в символах UTF-16, не в токенах.

| Размер Float32-векторов | 696 320 байт | 1 040 384 байта |

Время — сохранённые измерения первоначального построения, а не новая серия бенчмарков. FIXED запускался первым, STRUCTURAL — после прогрева модели. По этим двум измерениям нельзя заключать, что структурная стратегия всегда быстрее в несколько раз. Во время итоговой живой проверки Ollama показывал выполнение модели на **100% GPU**.

`splitCodeBlocks` считает блоки команд, в которых оказалась хотя бы одна внутренняя граница; не количество всех разрезов. STRUCTURAL не обещает сохранить любой блок целиком: длинные блоки и overlap могут разделять его. `vectorBytes` — только координаты векторов, не полный размер файла SQLite. Usage embedding batches не включает отдельные dimension probes.

## Диагностический поиск

В [контрольном наборе](../evaluation/day21-search-cases.json) пять вопросов, для каждого заранее указан ожидаемый файл. Из каждого индекса запрошены пять ближайших чанков. Проверялось наличие ожидаемого документа в этой пятёрке: `document_hit_at_5`.

| Вопрос | Ожидаемый источник | FIXED | STRUCTURAL |
| --- | --- | --- | --- |
| Разница reset --soft / --mixed / --hard | reset.asc | Найден в top-5 | Найден в top-5 |
| Merge, rebase и опубликованные коммиты | rebasing.asc | Найден в top-5 | Найден в top-5 |
| Stash и untracked-файлы | stashing-cleaning.asc | Найден в top-5 | Найден в top-5 |
| Объекты blob, tree, commit | objects.asc | Найден в top-5 | Найден в top-5 |
| Fetch и pull | remotes.asc | Найден в top-5 | Найден в top-5 |

Итого **5/5 для каждой стратегии**. Это небольшая smoke-проверка retrieval: она не доказывает, что лучший абзац всегда на первом месте, цитаты поддерживают будущий ответ или LLM отвечает правильно. Cosine similarity также не является вероятностью правильного ответа. В день 22 появятся генерация и отдельная оценка ответов.

### Вывод о chunking

FIXED проще и создаёт меньше векторов, но часто объединяет разные разделы. STRUCTURAL даёт более короткие, тематически ограниченные фрагменты без перехода через границы разделов; в этом корпусе реже разрезает блоки команд. Цена — больше чанков и больше места для векторов. На пяти контрольных вопросах обе стратегии нашли нужные документы, поэтому по этой метрике победителя нет. Для следующего дня разумный основной режим — STRUCTURAL, а FIXED остаётся baseline для сравнения.

## Проверки кода и приложения

- **Backend: 13 тестов прошли**, повторный запуск с `--rerun-tasks`, не только кеш Gradle. Chunking — 5, векторы/SQLite — 4, Ollama adapter — 3, настоящий корпус — 1. Failures/errors: 0.
- **Frontend: 1 unit-тест отчёта прошёл**, генерация API types, TypeScript-проверка и production-сборка прошли. `npm audit`: 0 обнаруженных уязвимостей при проверке.
- **UI: 5 Playwright-тестов прошли** в Chrome: документы/preview/вкладки, мобильная ширина 390px, сравнение/MD download/реальный поиск/источник, ошибочный overlap, запоздалый preview без самовольной смены вкладки. Desktop/mobile screenshots просмотрены отдельно.
- **Живой API:** оба сохранённых индекса совместимы; coverage=100%; тексты и обязательные метаданные не пусты; текст чанка совпадает с substring документа сохранённого snapshot; выполнены 10 локальных поисковых запросов.
- **Ошибочные запросы:** неизвестная стратегия, недопустимый overlap, сравнение одинакового index ID и пустой поисковый вопрос возвращают HTTP 400. Неизвестный индекс возвращает HTTP 404.
- **Persistence:** backend перезапущен отдельно, индексы и контрольный ranking сохранились; повторно вычислять документы не потребовалось.
- **Недоступность Ollama:** при первичной проверке остановленного runtime новое задание завершилось FAILED с объяснением, частичный индекс не опубликован, готовые индексы не потерялись. Runtime восстановлен. Такой FAILED job в истории — результат проверки отказа, не текущая неисправность.
- **Целостность корпуса:** повторная проверка manifest подтвердила SHA256 всех выбранных исходников и закреплённого include-ресурса.

В интерфейсе дополнительно устранена гонка: завершение preview/загрузки чанков больше не возвращает пользователя на прежнюю вкладку. Запрос поиска фиксирует исходный вопрос для обеих колонок; запоздалое сравнение не подменяет результат после изменения выбранных индексов.

## Повторить проверку

Из `rag`, в **PowerShell 7**:

```powershell
pwsh -File ./scripts/verify-live.ps1
```

Скрипт использует готовые индексы 3000/300; `-BuildIndexes` разрешает построить отсутствующие. Машиночитаемый отчёт — `data/live-verification.json`, исключён из Git. Измерения в этом MD зафиксированы для указанных index IDs; новый запуск с иными параметрами не переписывает этот документ автоматически.

В `client`: `npm ci`, `npm run build`, `npm test`, `npm run test:e2e` (нужны живое приложение, два индекса и установленный Chrome). Backend: `./gradlew.bat test --rerun-tasks`; если Windows Gradle не может создать loopback-соединение, используйте Docker/JDK 21, как описано в [Windows guide](windows-setup.md).

Сценарий записи видео — [day21-testing.md](day21-testing.md). Архитектура — [architecture.md](architecture.md), алгоритм по классам — [application-guide.md](application-guide.md). Схема [Archify](diagrams/day21-architecture.html) прошла showcase validation 9/9, browser containment и отдельный визуальный просмотр; [подтверждение](diagrams/day21-acceptance.md) фиксирует SHA файлов.
