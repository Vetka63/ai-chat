# День 24: сверка задания и решения

Первоначальная реализация проверяла дословность цитат автоматически, а их смысл — вручную. После обнаружения неподтверждённых утверждений с настоящими цитатами план дополнен отдельным `ClaimSupportValidator`. Таблица ниже описывает текущую реализацию; первоначальные решения и наблюдения сохранены отдельно как история. Новые автоматические проверки и незакрытая живая приёмка — в [day24-remediation.md](day24-remediation.md).

## Что было готово

День 23 сохранён как `6f7a581`. Есть русский Pro Git, два индекса одного snapshot, локальные embeddings, поиск, отбор по cosine, query rewrite, DeepSeek, десять вопросов с ожиданиями, UI и API usage. Они достаточны для реализации, но сами по себе не выполняют день 24: свободный ответ с упоминанием источника ещё не является проверенной цитатой.

Работа ведётся в отдельной ветке `ai-challenge-day-24`. Дни 22–23 и старые приложения не заменяются. История чата и task memory остаются днём 25.

## Требование → реализация → проверка

| Требование | Решение | Проверка |
|---|---|---|
| Ответ с источниками | Ответ состоит только из пунктов `claims`; каждый связан с источником | Нет отдельного свободного `answer` в JSON модели |
| source + section/chunk_id | Метаданные сервер извлекает из фактически переданного чанка | Поддельные IDs, внешние метаданные и бюджетно исключённые чанки отклоняются |
| Цитаты | Буквальные непрерывные фрагменты 20–600 символов, координаты UTF-16 | Substring и точное совпадение с index-scoped snapshot |
| Поддержка смысла цитатами | После ExactCitationValidator отдельный ClaimSupportValidator проверяет весь смысл каждого пункта и сохранение условий примера | При UNSUPPORTED/CONTRADICTED или неправильном ответе проверки весь результат INVALID_EVIDENCE; частичные claims/sources не публикуются |
| Слабая релевантность | Threshold gate до генерации: UNKNOWN + уточнение | Нерелевантные вопросы и высокий порог, 0 answer LLM calls |
| Контекст не содержит ответа | Модель может вернуть unknown даже при высоком score | Структура unknown, пустые claims, уточнение |
| Проверка 10 вопросов | До двух LLM-стадий на каждый контрольный вопрос без rewrite: генерация и проверка смысла | Автоматически проверяются presence, exactness, PASSED, индексы вердиктов и usage; качество вердиктов и полнота требуют также ручной оценки |
| Наглядность | Отдельная вкладка, точная цитата в документе, MD/JSON | Desktop/mobile, export, Escape, сохранение при переключении вкладок |

## Текущее дополнение к плану

`ExactCitationValidator` по-прежнему проверяет только форму и дословность. Его положительный внутренний результат ещё не разрешает публикацию. Следующий `ClaimSupportValidator` получает claims, собственные цитаты каждого пункта и контекст только цитируемых чанков. Окружающий текст может обнаружить потерянные предпосылки, но не считается заменой недостающего доказательства. Для PASSED требуются по одному явному SUPPORTED на каждый индекс и корректная структура JSON.

Истинный по общим знаниям ответ о `--soft` нельзя подтвердить цитатой только о `--mixed`. Равный итог двух книжных примеров merge/rebase нельзя расширять до универсального правила. Для таких случаев добавлены регрессии, а генератору явно предписано сохранять условия и границы источника. Проверяющая модель всё ещё способна ошибаться, поэтому новый этап не заменяет ручную приёмку и не проверяет истинность самого источника во внешнем мире.

Новый ANSWERED требует успешного прохождения обеих стадий. Неподдержанный смысл, противоречие, неполный или неверный вердикт закрывают ответ как INVALID_EVIDENCE. Сбой провайдера смысловой стадии даёт ERROR. UNKNOWN и неверная дословная цитата не запускают лишний вызов. Retry нет.

Успешная генерация без rewrite теперь использует два платных вызова, с rewrite — три. Технический лимит проверяющей модели — 2048 output tokens; он не меняет nullable лимит пользовательского ответа. `supportCheck.generation` сохраняет её расход и диагностику, общий usage/cost учитывает стадию один раз. При неизвестном расходе одной вызванной стадии общая сумма неизвестна. Новые traces получают timestamp и run ID, исторические результаты не перезаписываются.

## Исторические уточнения первоначальной реализации

Следующие пункты фиксируют прежнее решение и тогдашние прогоны. Пункт 4 об отсутствии отдельного judge и прежние утверждения об успешном live-прогоне не описывают текущую смысловую стадию; её качество пока не объявлено принятым.

1. JSON mode обеспечивает синтаксический JSON, но не соблюдение нашей схемы и не истинность. Поэтому отдельный `CitationValidator` обязателен. Обрезанный ответ тоже не принимается. [Документация DeepSeek](https://api-docs.deepseek.com/guides/json_mode/) описывает JSON mode и необходимость явной JSON-инструкции.
2. Проверяем именно **переданные** чанки, не весь поиск и не всю книгу. Иначе модель могла бы сослаться на текст, которого не видела.
3. Пробелы, регистр, переносы и разметка не «исправляются» ради прохождения проверки. UI показывает тот же канонический текст, по которому вычислены координаты.
4. `ANSWERED` означает, что структура и цитаты прошли проверку. Это не автоматическое доказательство смысловой поддержки. Отдельный платный judge не добавляем; оценку десяти вопросов фиксируем в отчёте.
5. Недостаточный бюджет — ошибка настройки, а не доказательство отсутствия знания. Ошибка провайдера — ERROR, не fallback к ответу без RAG.
6. Production `maxOutputTokens=null`: поле не отправляется, остаются ограничения провайдера. В скрипте тестов 2400 — только явный параметр эксперимента. Retry скрыто не расходует деньги.
7. Первый живой ответ опустил `clarification:null`, хотя все девять цитат совпали буквально. Для known это необязательное nullable поле; для unknown непустое уточнение обязательно. Это безопасная структурная вариация, не исправление неверных цитат. Добавлены regression tests; поддельные IDs и extra fields по-прежнему отклоняются.
8. Дополнительный вопрос вне десяти эталонов выявил подмену операции: вопрос о припрятывании получил цитируемый ответ про git add. Уточнена общая инструкция соответствия исходной цели и unknown при похожем, но неподходящем контексте. Повтор показал честный отказ; весь набор повторно проверен. Не заявляем абсолютную semantic-защиту на основании одного prompt.
