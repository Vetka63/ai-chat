# День 24: исправление проверки смысловой поддержки

Этот отчёт относится к ветке `ai-challenge-day-24` после добавления отдельного `ClaimSupportValidator`. [Первоначальный отчёт](day24-test-results.md) сохранён как история конвейера, проверявшего дословность цитат автоматически и смысл вручную. Его live-результаты и стоимость не являются проверкой новой стадии.

## Что исправлено

Реальная цитата не всегда подтверждает связанный с ней вывод. Утверждение может приписать действие одной опции другой или превратить частный книжный пример в универсальное правило. Одного substring-сравнения для этого недостаточно.

Текущая последовательность: генерация структурированного ответа → `ExactCitationValidator` → `ClaimSupportValidator` → публикация. Первый этап проверяет форму, принадлежность и дословность цитат; второй — полный смысл каждого пункта и сохранение условий его собственных цитат. Генератору также явно предписано сохранять предпосылки примера и не расширять подтверждённый вывод.

Проверяющая модель получает claims, их цитаты и окружающий текст только цитируемых чанков. Название раздела и окружающий текст помогают обнаружить потерянный контекст, но не заменяют недостающее доказательство. Другой пункт ответа, нецитируемый чанк и эталонные ответы не служат источниками. Проверка использует существующий настроенный LlmClient, без отдельного провайдера и без автоматических повторов.

## Публикация и диагностика

Новый ANSWERED допускается только после обеих проверок: `supportCheck.status=PASSED` и по одному SUPPORTED на каждый пункт. UNSUPPORTED или CONTRADICTED закрывает весь ответ как INVALID_EVIDENCE; публичные claims/sources пусты. Такой же карантин действует при неизвестном вердикте, пропущенном/повторном индексе, дубликате JSON-ключа, лишнем поле, trailing JSON или обрезанном ответе проверки. Сбой провайдера возвращает ERROR. Нет частичной публикации и fallback к ответу без RAG.

`supportCheck.generation` сохраняет сообщения, raw JSON, фактическую модель, finish reason, latency, usage и estimate даже при отклонении вердиктов. Это диагностический ответ модели, не дополнительное публичное доказательство. Поле `supportCheck` nullable с default null: старые JSON-результаты остаются читаемыми, но их прежний ANSWERED не означает прохождения нового этапа.

## Стоимость и ограничения

Успешный вопрос без rewrite использует две LLM-стадии, с rewrite — три. Проверка смысла имеет технический лимит 2048 output tokens. Он не меняет `maxOutputTokens=null` для пользовательской генерации; тестовый лимит 2400 в скрипте относится только к её экспериментальному запуску.

Общий usage/cost суммирует каждую выполненную стадию один раз. Если провайдер не вернул usage одной вызванной стадии, общая сумма остаётся неизвестной, а отдельные известные измерения сохраняются. При транспортной ошибке попытка учитывается, даже если ответ и usage стадии ещё не получены. Оценка стоимости не является подтверждённым списанием.

Смысловая проверка снижает риск неподтверждённых выводов, но сама может ошибаться. Она не доказывает истинность книги и не гарантирует полноту ответа. Совпадение с цитатой, поддержка смысла и техническая корректность вне конкретного примера оцениваются раздельно.

## Живая приёмка ещё не закрыта

Этот отчёт не объявляет десять контрольных ответов или реальную проверяющую модель прошедшими смысловую приёмку. Для неё нужны сохранённые новые результаты и чтение каждого claim вместе с цитатами и вердиктом. Автоматические проверки выше не заменяют этот этап.

`scripts/verify-day24.ps1` выполняет десять вопросов без rewrite — до 20 платных LLM-вызовов — и четыре ожидаемых отказа без генерации. Все полученные исходы сохраняются; обычный отказ по качеству не останавливает оставшиеся случаи и не вызывает retry. Итоговая проверка не считается успешной, если хотя бы один контрольный ответ отклонён. Новый trace имеет вид `data/day24-live-results-<UTC timestamp>-<run id>.json`; старые файлы не перезаписываются.

Отдельный `ClaimSupportLiveTest` включается только через `RAG_RUN_LIVE_SUPPORT=true`. Он делает четыре настоящих вызова checker на цитатах локального корпуса: три неподдержанных утверждения и один корректный пересказ. Его результаты сохраняются отдельно в `data/day24-support-live-<timestamp>-<run id>.json`. В обычном suite этот тест пропущен, поэтому число 76 passed не включает доказательство его качества. Условия запуска и стоимость каждого повтора приведены в [day24-guide.md](day24-guide.md).

Актуальный алгоритм — в [architecture.md](architecture.md), исходные решения и их пересмотр — в [day24-plan-review.md](day24-plan-review.md). Старый рисунок `diagrams/day24-grounding.html` создан до новой стадии и сохраняется как исторический артефакт.
