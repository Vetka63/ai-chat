# Сверка задания дня 25

День 25 добавляет диалог поверх проверенного RAG дня 24. Главный результат — не просто сохранённые строки чата, а новый поиск для каждого вопроса с учётом цели, уточнений и контекста разговора.

## Требования и реализация

| Требование | Решение |
| --- | --- |
| Мини чат | Отдельная вкладка «Чат с RAG и памятью», список чатов, ввод, ответы, цитаты |
| История диалога | SQLite `conversation_turns`; восстановление после reload и restart |
| RAG на каждом вопросе | Подготовка самостоятельного вопроса → SearchService → фильтр → GroundingService |
| Источники | Только технические пункты с валидными цитатами; UNKNOWN/ERROR не выдумывают источники |
| Память задачи | Отдельная таблица `task_memory`: GOAL, CLARIFICATIONS, CONSTRAINTS, TERMS |
| Два длинных сценария | `evaluation/day25-scenarios.json`: по 12 пользовательских сообщений, то есть 12 обменов |
| Цель не теряется | Общая цель защищена от замены промежуточными шагами и входит в каждый prompt |

## Пересмотр плана перед реализацией

Подготовка поискового вопроса и patch памяти объединены в один структурированный LLM-вызов. Иначе каждый turn потребовал бы отдельные extraction, rewrite и answer. Максимум здесь — две LLM-стадии: подготовка и ответ. Если релевантных источников нет, генерации ответа нет, но подготовка уже была оплачена. Usage каждой стадии хранится отдельно.

Индекс и настройки закрепляются при создании чата. Это воспроизводимый эксперимент: нельзя незаметно сменить корпус в середине разговора. Другую конфигурацию проверяют в другом чате. Сохраняется вся история, однако в модели — ограниченный хвост целых обменов и компактная память. Какие сообщения не вошли, видно в диагностике; сами сообщения из БД не удаляются.

Пользовательское сообщение записывается до сети. Один pending turn на чат, optimistic revision и idempotency key исключают обычную двойную генерацию из параллельных вкладок. Нет скрытых retries. При рестарте pending отмечается INTERRUPTED, а не исчезает.

## Границы гарантий

Точные цитаты памяти подтверждают происхождение из user message, но не автоматически доказывают правильность пересказа. Точные цитаты книги также не доказывают правильность вывода. Автоматический semantic judge не добавлен.

Глобальная цель и локальный шаг различаются. Первое извлечение заполняет цель. Дальше сервер не разрешает модели заменить её промежуточным пожеланием. Для явной смены пользователь начинает сообщение с «Новая цель:», «Измени цель:» или «Моя новая цель:». Остальные слои не очищаются; для независимой задачи лучше новый чат.

Это локальное production-like приложение, не готовая многопользовательская система: нет authentication, tenant isolation или распределённой аренды pending turns. Startup recovery рассчитан на один backend. Для нескольких реплик нужны lease/fencing и миграции, а не копирование текущего recovery-кода.
