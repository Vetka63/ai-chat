# Запись видео: дни 24 и 25 — реальные результаты 5 октября

Откройте **http://localhost:8383/**. Для записи удобнее обычный браузер во весь экран: на узком экране панель памяти располагается под чатом. Ветка — `ai-challenge-day-25`, она содержит и раздел дня 24. Это демонстрация настоящих сохранённых результатов, не подставленные ответы.

## День 24 — отдельные ответы, не чат

1. Нажмите слева **«Источники и цитаты»**.
2. В **«Сохранённые результаты»** выберите ответ о `git status` либо `stash`.
3. Покажите исходный вопрос, ответ, цитату и строку `source / section / chunk_id` под ней.
4. Нажмите **«Открыть цитату в источнике»**. Приложение сверяет её с сохранённым снимком книги. Раскройте **«Документ целиком с подсветкой цитаты»**.
5. Закройте окно. Разверните **«Поиск и реально переданный контекст»** — это найденные фрагменты, из которых модель составляет ответ, а не полная книга.
6. Покажите **«Проверка смысловой поддержки · PASSED»**. Это дополнительный вердикт модели, не гарантия безошибочности. Исходные черновики находятся отдельно в диагностике.
7. В сохранённом списке выберите **«Какая погода будет завтра в Самаре?»** с порогом **0,60**. В настоящем UI-прогоне получены `UNKNOWN`, просьба уточнения и **0 LLM-стадий**: ответ не выдуман из отсутствующих источников. Есть и отдельная проверка с намеренно строгим порогом 1.
8. Обновите страницу и вернитесь в раздел: результаты остаются в этом браузере. Переключение между ними не вызывает LLM.
9. Скачайте MD и JSON кнопками под ответом.

Результаты, полученные тестовым API-скриптом, открываются через **«Открыть ранее скачанный JSON без нового запроса к LLM» → «Импорт JSON-ответов»**. Можно выбрать до 20 файлов одновременно. Импортируйте файлы `video-day24-…-result.json`, не `…-report.json` и не общий `…-set…json`. Они лежат в `F:\ai-advent-challenge\ai-chat\rag\data`. Не выделяйте все JSON этой папки: там есть старые и служебные отчёты.

В UI импорт честно подписан как импорт: приложение не может удостоверить происхождение произвольного файла. У этих демонстрационных файлов ответы получены реальным API и отдельно сверены с цитатами; импорт сам по себе не делает новый запрос и не проводит новую смысловую проверку. Время импорта не является временем генерации.

Фраза для видео:

> «Показываю сохранённые результаты реального прогона. Для каждого опубликованного пункта есть цитата и ссылка на фрагмент книги. При отсутствии подходящего контекста приложение не придумывает технический ответ».

## День 25 — настоящие диалоги в базе

### Основной сценарий: stash

1. Нажмите **«Чат с RAG и памятью»**.
2. Выберите **«Видео день 25 — безопасная работа со stash · 05.10»**.
3. Прокрутите переписку к началу. В первом сообщении сформулированы цель — памятка по сохранению незакоммиченной работы — и запрет удалять запись stash.
4. Покажите панель **«Память этого чата»**. В ней отдельно видны цель, ограничения и уточнение о неотслеживаемом файле.
5. В сообщениях 6–8 покажите вопрос про untracked-файл и короткие продолжения «эта опция» / «а какая опция». Ответы различают `-u` и `-a` и содержат новые найденные источники.
6. Прокрутите к последнему, десятому сообщению. В принятом ответе предлагается `git stash apply`, сохраняющий запись, а не удаление через pop/drop.
7. Разверните **«Источники и цитаты»**, затем **«Открыть цитату в книге»**. Покажите подлинный фрагмент про apply и сохранение записи.
8. Разверните **«Как получен ответ»**. Видно: **6 обменов в prompt, 3 вне prompt**. Полная история при этом хранится и доступна в чате.
9. У цели и запрета в панели памяти раскройте **«Откуда запомнили»** → **«К сообщению пользователя»**. Их источник — первое сообщение, уже отсутствующее в хвосте последнего запроса.
10. Покажите также третье сообщение: оно было ошибочно отклонено строгой проверкой. Его не удаляли и не заменяли. Реальный результат этого чата — **9 ANSWERED из 10**, а не 10/10.
11. Скачайте **«Скачать чат MD»** и **«Скачать диагностику JSON»**.

Последний вопрос сам повторяет часть ограничения. Поэтому этот прогон доказывает сохранение ранней памяти вне хвоста и согласованность ответа с ней, но не отдельный эксперимент «ответ возможен только благодаря памяти». Не утверждайте больше показанного.

### Второй независимый сценарий

Выберите **«Видео день 25 — проверка перед коммитом · 05.10»**. Здесь другая цель, запрет удаления файлов и имя `docs/guide.md`; они не смешаны с памятью stash-чата.

Покажите вопросы про `git status`, обычный `git diff` и `git diff --staged`, затем короткие продолжения темы. У опубликованных ответов раскрываются свои источники. В шестом сообщении был `UNKNOWN`: нужный фрагмент про `--cached = --staged` нашёлся, но не прошёл порог 0,60. Это ограничение поиска, хотя в книге ответ есть. Третье сообщение также осталось без принятого ответа.

Не выдавайте эти отказы за успешные полезные ответы. Итог второго чата: **8 ANSWERED, 1 INVALID_EVIDENCE, 1 UNKNOWN**, все десять сообщений сохранены.

## Перезапуск и честная интерпретация

Backend действительно перезапускался после первых шести сообщений обоих новых чатов. Продолжение выполнялось в тех же чатах. Первый автоматический скрипт доказательства не успел подтвердить readiness из-за слишком короткого HTTP timeout 2 секунды; его незавершённый trace сохранён и не объявляется успешным совпадением хешей.

Точная повторная сверка после завершения диалогов выполнена без PENDING-запросов: **MATCH для обоих чатов**. Отчёт: `data/video-restart-20261005T071509055.json`. Для каждого чата совпали SHA-256 полного объекта conversation + memory + turns (по 10 обменов). Backend возвращён на обычный API, тома данных не удалялись. Обновление одной страницы само по себе не доказывает перезапуск сервера.

Это компактный демонстрационный набор. Он не заменяет более строгую многократную приёмку из `day24-25-confidence-plan.md`, старые неудачные результаты остаются сохранёнными.

Защита от выдуманных цитат не ослаблялась; отказы и исходные traces не удалялись. Исходная строгая многократная приёмка ещё не пройдена.

Новые автоматические платные тесты требуют снова включить его, используя существующий ledger, а не новый лимит с нуля.

Ветка: `ai-challenge-day-25`; backend в этом проходе не менялся. День 24 показывается в составе этой ветки. Другие учебные ветки и main не изменялись.
