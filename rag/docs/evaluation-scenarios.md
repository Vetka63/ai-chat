# Сценарии оценки

Один корпус, одна модель и одинаковые вопросы используются при сравнении стратегий. В дне 21 оцениваем retrieval и целостность индекса, а не ответы LLM. Содержимое исходных файлов важнее заранее угаданного рейтинга.

## День 21: диагностический поиск

Машиночитаемые случаи: `evaluation/day21-search-cases.json`. Для каждого запроса запускаем topK=5 на FIXED и STRUCTURAL и сохраняем найденные `source`, `section`, `chunkId`, score.

Основная простая метрика — document hit@5: присутствует ли хотя бы один ожидаемый source среди пяти результатов. Она **не доказывает**, что правильный абзац найден или ответ верен. Отдельно просматриваем содержимое top chunks. Более низкий cosine другой стратегии сам по себе не означает худшее качество.

Сценарии: три дерева Git/reset, различия merge/rebase, stash untracked, содержимое Git objects, fetch/pull. Добавляются нерелевантный вопрос о погоде и короткий неоднозначный запрос для наблюдения, но отказ при слабом контексте будет реализован в дне 24.

## 10 вопросов для дней 22–24

Это подготовленный список ожиданий, не импортированный «готовый русский RAG benchmark». Перед днём 22 ожидания нужно сверить с snapshot вручную; не добавлять вопрос/ответы в индекс.

| № | Вопрос | Что ожидаем | Источник |
|---|---|---|---|
| 1 | Что изменяют reset --soft, --mixed и --hard? | HEAD, index, working tree; риск потери локальных изменений у hard | `reset.asc` |
| 2 | Чем merge отличается от rebase и почему нельзя бездумно rebase общую опубликованную ветку? | Разная история, переписывание коммитов и последствия совместной работы | `rebasing.asc` |
| 3 | Как stash сохранить untracked-файлы? | Роль -u/--include-untracked; отличие от ignored | `stashing-cleaning.asc` |
| 4 | Чем git fetch отличается от git pull? | Получение объектов/remote refs против получения и интеграции | `remotes.asc` |
| 5 | Как отменить изменение файла и чем опасна эта команда? | Восстановление из index/коммита, потеря несохранённой работы; не универсальный совет | `undoing.asc` |
| 6 | Какие состояния файла выделяет Git и что делает git add? | Modified/staged/committed, снимок для следующего коммита | `recording-changes.asc` |
| 7 | Почему указатель ветки в Git считается лёгким? | Указатель на коммит, роль HEAD | `nutshell.asc` |
| 8 | Какие объекты Git описывают содержимое и структуру коммита? | Blob/tree/commit и связи между ними | `objects.asc` |
| 9 | Как бинарным поиском найти коммит, внесший ошибку? | Bisect, good/bad, сужение диапазона | `debugging.asc` |
| 10 | Что такое submodule и почему это не просто скопированная папка? | Отдельный repository и фиксируемый commit, работа clone/update | `submodules.asc` |

Для grounded evaluation сначала зафиксировать правильный фрагмент и quote каждого вопроса. Сейчас expected source — ориентир по файлу, а не gold chunk ID: chunk IDs различаются между стратегиями.

## Негативные и технические проверки

- Пустой запрос, неверная стратегия, overlap >= половины размера → понятный HTTP 400, а не новый индекс.
- Ollama offline/модель не загружена/неверный JSON/vector count/dimension/нулевой вектор → явная ошибка, без публикации частичного индекса.
- Restart при RUNNING → FAILED job; restart после READY → готовый индекс, snapshot и вектора сохранены.
- Изменённая модель/digest → поисковый запрос старого индекса отвергается, не смешивает пространства.
- Оба chunker покрывают весь нормализованный текст; структурный раздел может быть разделён при превышении maxCharacters.
- Документы книги отображаются как текст; команды из книги не исполняются, внешние include не разрешены.
- Desktop и mobile: страницы читаются, таблицы прокручиваются внутри, нет горизонтального overflow всей страницы.

Измерения этого запуска и ограничения — в `test-results.md`.
