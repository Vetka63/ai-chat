# День 16 · Проверка MCP-подключения

Задание: клиент устанавливает MCP-соединение и получает список доступных
инструментов. Для воспроизводимой проверки используется локальный сервер,
входящий в Python-бэкенд. Ключ DeepSeek и доступ к интернету ему не нужны.

Схема реализованного пути: [интерактивный HTML](day16-mcp-discovery.html) и
[редактируемый JSON Archify](day16-mcp-discovery.sequence.json). Подписи самой
схемы русские, служебные кнопки просмотрщика Archify пока отображаются на
английском.

## Через интерфейс

1. Запустите Python backend и `ai-agents-client` обычным способом или через
   `docker compose up -d --build agents-backend agents-client`.
2. Откройте `http://localhost:8083/` (Docker) либо `http://localhost:5174/`
   (локальный Vite).
3. В левой колонке нажмите **MCP · День 16**. Откроется отдельный экран, а не чат.
4. В каталоге увидите **Локальный учебный сервер**. Нажмите
   **Подключиться и получить инструменты**.
5. Убедитесь, что появилась надпись «Соединение проверено», версия протокола
   и два инструмента: `add_numbers`, `echo_text`. Раскройте у любого инструмента
   схему входных параметров.
6. Нажмите **Проверить ещё раз**: бэкенд создаст новое соединение и снова
   прочитает `tools/list`. После каждого ответа соединение закрывается.
7. Выберите сохранённый чат или нажмите **Новый чат**, чтобы вернуться к
   прежнему интерфейсу агента.

## Без UI

Из каталога `ai-agents-backend` после установки зависимостей:

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe -m capabilities.mcp_discovery
```

Команда выводит JSON с `server`, `server_name`, `protocol_version` и массивом
`tools`. Это тот же MCP-клиент, который обслуживает UI.

HTTP-вариант: `GET /api/v1/mcp/servers`, затем
`POST /api/v1/mcp/servers/local-demo/discover`. Неизвестный ID возвращает
`404 mcp_server_not_found`. Если процесс сервера недоступен, UI получает
понятную ошибку, а внутренние подробности остаются только в логах backend.

## Что именно проверяется

`async with Client(StdioServerParameters(...))` запускает локальный сервер и
согласовывает MCP-протокол. Затем `list_tools()` получает реальные объявления
инструментов, включая имена, описания и входные схемы. Это не зашитый в UI
список. На этом День 16 заканчивается: tools пока не вызываются и не
подключаются к LLM.

Код расположен в `src/capabilities/mcp_discovery/`, HTTP-маршрут — в
`src/application/routes/mcp.py`, UI — в `ai-agents-client/src/features/mcp/`.
