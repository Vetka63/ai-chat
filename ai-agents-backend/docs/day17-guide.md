# День 17: первый MCP-инструмент в чате

## Что реализовано

Учебный каталог вымышленных игр работает как **отдельный HTTP-сервис** в Docker
(`games-mock-api`, порт `8084`). Он хранит название и краткое описание каждой игры
в `ai-games-mock-api/games.json`. `GET /games?query=...` ищет слова в этих двух
полях; незнакомая игра даёт пустой список. Сервис ничего не знает о LLM.

Отдельный проект [`python-mcp-games`](../../python-mcp-games/README.md)
запускает MCP-сервер `games-mock` по Streamable HTTP (`/mcp`). В нём
зарегистрирован инструмент `search_games(query: str)`: объявленная SDK схема
содержит обязательный строковый параметр `query`. Реализация обращается к
HTTP mock API и возвращает `query` и массив `games`.

Для сравнения рядом с ним расположен самостоятельный проект
[`java-mcp-games`](../../java-mcp-games/README.md) на Spring Boot/Spring AI.
Он объявляет тот же `search_games` через Streamable HTTP (`/mcp`) и получает
игры из того же mock API. В списке подключений чата это `java-games-mock`.

В UI агент **«Игровой MCP-агент»** создаёт собственный чат. При создании можно
задать начальный набор серверов или оставить его пустым. У поля ввода меню
«MCP» позволяет отметить серверы **для каждого сообщения** и снять все
галочки. Выбранный набор сохраняется вместе с вопросом. `local-demo` Дня 16 остаётся в MCP-обозревателе, но
в чат не подключается. Это не позволит браузеру подменить адрес MCP-сервиса.

## Путь одного сообщения

1. Пользователь выбирает MCP у поля ввода и спрашивает об игре. Бэкенд
   проверяет ID по серверному разрешённому списку и сохраняет вопрос с выбором в SQLite.
2. Агент получает список инструментов выбранных серверов через MCP
   `tools/list` и переводит их JSON Schema в `tools` Chat Completions API.
3. DeepSeek или Mistral решает, вызывать ли инструмент, и при необходимости
   возвращает `tool_calls` с аргументами. Модель **не выполняет** HTTP-запрос.
4. Агент проверяет имя инструмента по разрешённому списку, MCP-клиент
   вызывает `tools/call`, а MCP-сервер обращается к mock API.
5. Результат сохраняется в отдельной таблице `mcp_tool_events` и показывается
   в чате между вопросом и ответом. Затем агент передаёт результат модели,
   получает итоговый ответ и сохраняет его в историю.

Если все MCP отключены, агент не делает `tools/list` и не передаёт модели
инструменты. В таком ответе он не должен утверждать, что проверил каталог.
Если модель отвечает без инструмента, второго вызова LLM нет. Если инструмент
недоступен, ошибка выводится пользователю, вопрос остаётся в истории, а
сохранённый след ошибки доступен после обновления страницы. В рамках одного
сообщения допускается не больше трёх вызовов инструмента; повторного цикла
вызовов после финального ответа пока нет. Метаданные игр не следует считать
фактами о реально существующих играх.

## Как проверить через UI

1. В корне репозитория запустите
   `docker compose up -d --build games-mock-api python-mcp-games java-mcp-games agents-backend agents-client`.
   Ключ DeepSeek задаётся локально через `PY_AGENT_API_KEY` или `LLM_API_KEY`.
   Если ключа нет, установите `PY_AGENT_MODE=demo` в локальном `.env` и
   пересоздайте Python-бэкенд; demo повторяет тот же цикл без платного LLM.
2. Откройте <http://localhost:8083/>, справа выберите «Игровой MCP-агент».
3. Слева нажмите «Новый чат». Отметьте «Каталог игр · Python» и создайте
   чат. У поля ввода появится меню `MCP · 1`.
4. Спросите: `Какая игра в каталоге про космос?` Ожидается «Звёздные тропы».
   Между вопросом и ответом раскройте карточку `MCP · games-mock / search_games`:
   там видны аргумент `query` и запись каталога.
5. Спросите: `Найди «Лунный архив»`; проверьте другой результат. Обновите
   страницу: история и следы MCP-вызовов должны остаться.
6. В меню MCP у поля ввода снимите все галочки и задайте новый вопрос.
   Под вопросом должно быть `MCP отключены`, а карточки вызова инструмента — нет.
   Затем отметьте только Java-сервер и отправьте ещё один вопрос. У него будет
   `MCP: java-games-mock` и соответствующая карточка вызова. Выбор Python у
   старых сообщений при этом не изменится.
7. В разделе «MCP» слева можно увидеть учебный сервер и оба игровых MCP-сервера,
   а также отдельно выполнить обнаружение их инструментов.

Для сравнения можно создать второй чат или переключить галочки в текущем,
выбрав **только** «Каталог игр · Java / Spring Boot». Задайте тот же вопрос. Карточка вызова покажет
`java-games-mock / search_games`; структура и содержимое найденной игры
должны совпасть с Python-вариантом. Формулировка итогового ответа LLM
не обязана быть одинаковой. Для чистого сравнения не отмечайте оба сервера
одновременно для одного вопроса.

Проверить mock API отдельно: <http://localhost:8084/games?query=космос>.
MCP-адреса: Python — `http://localhost:8086/mcp`, Java —
`http://localhost:8085/mcp` (это не обычные веб-страницы).
Проверить серверный список: <http://localhost:8082/api/v1/mcp/servers>.

## Где менять функциональность

- Игры и HTTP-поиск: `ai-games-mock-api/app.py`, `games.json`.
- Python MCP-инструмент: `python-mcp-games/src/python_mcp_games/server.py`.
- Java MCP-инструмент: `java-mcp-games/src/main/java/com/example/javamcpgames/catalog/GamesTools.java`.
- Разрешённые MCP-серверы, `tools/list` и `tools/call`:
  `src/capabilities/mcp_discovery/service.py`.
- Правила и цикл агента: `src/agents/mcp_games/agent.py`, `prompts.py`.
- DeepSeek/Mistral tool calling: `src/infrastructure/tool_completions.py`.
- Следы вызовов: `src/infrastructure/sqlite_mcp_events.py`.
- UI выбора и следов: `ai-agents-client/src/components/NewChatDialog.vue`,
  `ChatThread.vue`.

Архитектура и связи сервисов визуализированы через Archify:
[интерактивная схема двух HTTP-сервисов](day17-http-mcp-comparison.html) и
[её спецификация](day17-http-mcp-comparison.architecture.json).
Авторские подписи схемы на русском; фиксированные элементы интерфейса Archify
отображаются на английском.
