# День 18-v2: архитектура и проверка

## Цепочка

Java mock API → SQL-каталог → Java MCP → агент игровых сводок
→ Python Feed MCP → SQLite с расписанием и отчётами → UI.

Разделение ответственности:

- mock-games-server (Spring Boot + H2) сохраняет **все** игры и генерирует
  по одной каждые 30 секунд;
- java-mcp-games предоставляет инструмент get_new_games, который получает
  из Java mock API максимум десять новых игр после курсора;
- python-mcp-game-feed хранит подписки, курсоры и отчёты в SQLite,
  но не каталог игр;
- отдельный процесс game-feed-worker проверяет наступившее расписание каждые
  5 секунд и вызывает GameDigestAgent; интервал **выпуска** — 5 минут;
- агент запрашивает MCP, формирует текст и сохраняет выпуск через MCP;
- UI показывает три последних выпуска, каждый с максимум десятью новыми
  играми. Разные чаты имеют отдельные курсоры.

Если между выпусками накопилось более десяти игр, отчёт показывает десять
последних из них. Оставшиеся игры не удаляются из Java SQL-базы. Курсор сдвигается
на ID самой новой игры, поэтому в следующем выпуске те же десять не
повторятся. Пустой выпуск возможен, когда новых игр нет.

## Проверка через UI

1. На ветке ai-challenge-day-18-v2 запустите из корня репозитория:
   docker compose -p ai-chat-day-18-v2 up -d --build agents-client game-feed-worker.
   Не используйте down -v: он удаляет данные.
2. Откройте http://localhost:8083, выберите агента «Игровые сводки»
   и создайте чат. В панели сводок запустите подписку. Интервал фиксирован:
   5 минут. Сразу будет видно время следующего запуска. Существующие активные
   подписки на 30 минут при обновлении сервиса переводятся на 5 минут.
3. Откройте http://localhost:8084/games/latest?after_id=0&limit=10.
   Запишите latest_id. Через 30 секунд повторите вызов: ID и количество
   выросли, предыдущая игра осталась.
4. Через 5 минут обновите отчёты в UI. Должна появиться сводка с не более
   чем десятью новыми играми. Через следующие 5 минут появится новый выпуск,
   без повторения игр из предыдущего.
5. Перезапустите контейнеры обычным docker compose -p ai-chat-day-18-v2 restart:
   каталог и подписка/сводки должны сохраниться.

Для ускоренной автоматической проверки GameRepositoryTest подтверждает
отсутствие обрезания SQL-каталога; test_game_digest.py проверяет передачу
только десяти игр. Запуск по расписанию можно проверить на отдельной
тестовой подписке, временно сдвинув только её next_run_at в SQLite, не
меняя пользовательский пятиминутный интервал.

LLM-ключ этому сценарию не нужен: агент создаёт проверяемую сводку из данных
MCP без дополнительной генерации. Для продакшена потребуются аутентификация,
устойчивая распределённая очередь и мониторинг фонового процесса.
