# День 10. Три стратегии управления контекстом

Ветка `ai-challenge-day-10` развивает День 9. При создании каждого чата один и тот
же диалоговый агент получает собственную стратегию. После создания она неизменяема:
для другого эксперимента создаётся отдельный чат. Java-проект и старый Vue-клиент
не меняются.

## Запуск

Из корня репозитория:

```powershell
docker compose -p ai-chat-day-9 stop agents-client agents-backend
docker compose -p ai-chat-day-10 up -d --build agents-backend agents-client
```

UI: http://localhost:8083, backend: http://localhost:8082. Для обычного
перезапуска не используйте `down -v`: этот флаг удаляет SQLite volume.

## Что доступно в UI

Кнопка «Новый чат» открывает форму с названием, стратегией и её параметрами.
`full` и `summary` оставлены как контрольный режим и совместимость с Днём 9.
Три новые стратегии соответствуют заданию:

1. **Sliding Window** — задайте N. В модель уйдут только последние N сохранённых
   сообщений, хотя в SQLite и на экране останется вся история.
2. **Sticky Facts** — перед каждым основным ответом служебный LLM-вызов обновляет
   ключевые факты, затем основной вызов получает facts + последние N сообщений.
   UI показывает текущий JSON как список, revision и отдельные расходы `Facts`.
3. **Branching** — сохраните checkpoint в текущем конце диалога, назовите два
   варианта и создайте их. Дочерние чаты появятся под родителем слева. Их можно
   продолжать и переключать независимо.

Настройка сохраняется у конкретного разговора и затем показывается в правой панели
только для чтения. Попытка изменить её через HTTP возвращает
`409 context_settings_immutable`. Любое N от 1 до 100 доступно для оконных стратегий.
Summary использует чётное N, чтобы не разрывать обычную пару вопрос/ответ.

## Один сценарий для проверки (12 сообщений)

Создайте два чата с одной моделью: Sliding Window и Sticky Facts, N=4. По очереди
отправьте одинаковые шесть реплик пользователя; ответы модели дадут 12 сообщений:

1. «Мы собираем ТЗ проекта Маяк. Цель — сервис записи к врачу».
2. «Пользователи: пациент и администратор».
3. «Бюджет 500 тысяч рублей».
4. «Исправление: бюджет 700 тысяч рублей, старое число не использовать».
5. «Технологии: Python, Vue и SQLite для прототипа».
6. «Срок — 30 ноября. Перечисли все согласованные требования, особенно цель и бюджет».

При N=4 ранняя цель уже выпала из Sliding Window. Sticky Facts должна сохранить
её в facts и учесть исправленный бюджет. Это не гарантия качества LLM, поэтому
сравнивайте фактические ответы и метрики, а не только наличие блока facts.

Для Branching создайте третий чат сразу со стратегией Branching и соберите общее ТЗ
первыми четырьмя репликами. Создайте checkpoint «Выбор архитектуры» и ветки
«Монолит» и «Микросервисы». В первой напишите «Выбрали модульный монолит», во
второй — «Выбрали три микросервиса». Затем в обеих спросите «Какую архитектуру
мы выбрали?». Ответы и новые сообщения должны быть независимыми.

## Что сравнивать

- сохранение ранних целей, ограничений и исправлений;
- размер реально отправленного prompt и число исключённых сообщений;
- число API-вызовов, токены, стоимость и задержку;
- отсутствие данных соседней ветки;
- восстановление чатов, facts и checkpoint после перезапуска backend.

Кнопка «Скачать MD-отчёт» сохраняет стратегию, messages, usage, facts и положение
в дереве. Отчёт может содержать пользовательские данные — проверяйте файл перед
публикацией.

Тот же сценарий можно воспроизвести скриптом. Без `--execute` он ничего не меняет;
с флагом создаёт видимые в UI тестовые чаты и выполняет около 26 LLM-вызовов:

```powershell
cd ai-agents-backend
.venv\Scripts\python.exe scripts\day10_experiment.py
.venv\Scripts\python.exe scripts\day10_experiment.py --execute
```

Результат записывается в `docs/day10-results.json`: ответы, facts, обе ветки,
все runs, известные API-токены и оценочная стоимость. Скрипт не удаляет чаты.

## HTTP API ветвления

```http
POST /api/v1/agents/dialogue/conversations/{conversation_id}/checkpoints
{"title":"Выбор архитектуры"}

POST /api/v1/agents/dialogue/checkpoints/{checkpoint_id}/branches
{"names":["Монолит","Микросервисы"]}

GET /api/v1/agents/dialogue/conversations/{conversation_id}/checkpoints
```

Создание checkpoint и веток само LLM не вызывает. Повторно создать ветки из одного
checkpoint нельзя. `GET conversation` возвращает `facts`, `checkpoints`, метаданные
дерева и runs всех типов: `dialogue`, `summary`, `facts`.

## Ограничения

- Sticky Facts использует модель выбранного чата с temperature=0, но извлечение
  всё равно может ошибиться. При ошибке старое состояние сохраняется.
- Facts-вызов добавляет задержку и стоимость на каждое пользовательское сообщение.
- Sliding Window может забыть критичный ранний факт; это ожидаемое свойство.
- Ветки копируют снимок, а не связывают изменяемую историю. Автоматического merge нет.
- Собственного блокирующего лимита контекста по-прежнему нет; лимит проверяет API модели.
