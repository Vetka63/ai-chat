# День 8 — работа с токенами

Ветка `ai-challenge-day-8` продолжает День 7. Java backend и прежний Vue-клиент не меняются.
Сжатия истории Дня 9 здесь **нет**. Полная история хранится в SQLite и передаётся в API.

## Запуск

Из корня репозитория:

```powershell
docker compose -p ai-chat-day-8 up -d --build agents-backend agents-client
```

Клиент: http://localhost:8083, API: http://localhost:8082. Порты не могут одновременно
занимать контейнеры Дня 7 — перед переключением остановите их, не удаляя тома:

```powershell
docker compose -p ai-chat-day-7 stop agents-client agents-backend
```

Том Дня 8 — `ai-chat-day-8_agents-data`. При первом развёртывании в него скопирован
один существующий чат Дня 7. Исходный том `ai-chat-day-7_agents-data` сохранён.
Не запускайте `down -v`, если хотите сохранить историю.

Ключи находятся только в локальном `.env`: DeepSeek — `PY_AGENT_API_KEY` либо `LLM_API_KEY`,
Mistral — `MISTRAL_API_KEY`. Клиент получает только признак настройки ключа, не сам секрет.
Тексты запросов и ответов не пишутся в логи; логируются модель, количества, finish_reason и коды ошибок.
В SQLite тексты хранятся открыто: это локальная учебная система без авторизации пользователей.

Для запуска без Docker установите `pip install -e ".[dev]"` из backend, загрузите tokenizer:

```powershell
python scripts/download_tokenizer.py tokenizers/ministral-3b
$env:PY_AGENT_MISTRAL_TOKENIZER_PATH="tokenizers/ministral-3b/tekken.json"
uvicorn application.main:app --app-dir src --port 8082
```

Затем `pnpm dev` из `ai-agents-client`. Без указанного пути tokenizer Mistral использует
приблизительную оценку; интерфейс честно сообщает выбранный метод. Docker скачивает
официальный tokenizer на этапе сборки, с фиксированной ревизией, без весов модели.

## Что проверять в UI

1. Создать чат. Выбрать Flash, Pro или Ministral в боковой панели.
2. Написать сообщение. До отправки видны токены текста, истории, системного промпта и всего запроса.
3. После ответа раскрыть строку модели: фактические input/output/total, cached/reasoning,
   время, finish_reason, запрошенная и возвращённая модели.
4. Продолжить чат длинными сообщениями. Таблица «Рост токенов» показывает вход и выход
   каждого вызова, а сумма включает повторно отправляемую историю.
5. Сменить модель в этом же чате: следующая модель получает ту же историю, предыдущие
   метрики не пересчитываются. Выбранная модель сохраняется после перезапуска.
6. Скачать MD-отчёт с метриками и источниками тарифов.

Модель не переключается автоматически. Каталог находится в `src/application/models.json`.
Отсутствующий API-ключ выключает выбор соответствующего провайдера.
Переключение DeepSeek → Mistral означает передачу истории этому другому провайдеру.

## Лимиты и точность

- Своего бюджета контекста нет; ни агент, ни UI не обрезают запрос по токенам.
- `max_tokens=1200` — отдельный лимит **ответа** агента, а не собственное окно контекста.
  Заполнение показывается как `(prompt + резерв ответа) / окно модели`.
- Ministral: официальный tokenizer. API модели `GET /v1/models/ministral-3b-2512`
  10.09.2026 вернул `max_context_length=131072`; именно это значение стоит в каталоге.
  Страница модели при этом рекламирует 256k: для этой интеграции ориентируемся на API.
- DeepSeek: эвристика UTF-8 / 3 + служебные токены, **не точная токенизация**.
  В проверке оценка 277 против фактических 141 токена. Финальные расходы всегда из usage API.
- Nginx допускает тело до 20 MiB. Это технический HTTP-предел, не лимит контекста агента.
  Его достаточно для приведённого эксперимента. При превышении ответит 413, а не ошибка окна модели.
- Таймаут LLM по умолчанию 90 с, настраивается до 300 с через
  `PY_AGENT_REQUEST_TIMEOUT_SECONDS`; nginx ждёт до 330 с.
- Очень длинный текст в UI свёрнут; это только отображение, API получает его полностью.

## Различаем ошибки

| Код | Что произошло |
|---|---|
| context_limit_exceeded | Провайдер отклонил контекст (обычно HTTP 400/422) |
| rate_limit | Квота, запросы или токены в минуту; не переполнение окна |
| request_too_large | Ограничение размера HTTP-тела |
| provider_timeout | Не дождались ответа; расход неизвестен |
| provider_auth | Ключ/доступ к модели |
| empty_output | Пустой ответ; usage всё равно сохраняется, если получен |
| app_restarted | Запуск был незавершён при перезапуске; расход неизвестен |

После ошибки вопрос остаётся в истории. Поэтому переполненный чат останется переполненным
даже при отправке короткого следующего вопроса. Создайте новый чат или выберите модель
с большим окном. Автоматическую компрессию добавим отдельной веткой в Дне 9.

## Эксперимент для видео

```powershell
cd ai-agents-backend
.venv/Scripts/python.exe scripts/day8_experiment.py
.venv/Scripts/python.exe scripts/day8_experiment.py --execute --output docs/my-day8-results.json
```

Без `--execute` скрипт не вызывает LLM. С флагом создаёт отдельный чат и выполняет до трёх
запросов: короткий → длинный → переполнение. Оценка калибруется через бесплатный preview.
Программа не повторяет платные запросы автоматически и останавливается при ошибке.
Синтетические большие тексты видны в UI. JSON содержит метрики, без ключей и текстов диалога.
Для короткой проверки DeepSeek: `--model deepseek-v4-flash --through short --execute`.

## Фактические результаты 10.09.2026

| Сценарий Ministral | Prompt локально | Input API | Output API | Total API | USD ≈ | Итог |
|---|---:|---:|---:|---:|---:|---|
| Короткий | 137 | 137 | 3 | 140 | 0.000014 | Ответ |
| Длинный | 8 156 | 8 156 | 68 | 8 224 | 0.0008224 | Ответ |
| Переполнение | 145 870 | неизвестно | неизвестно | неизвестно | неизвестно | HTTP провайдера 400, context_limit_exceeded |

Вход вырос примерно в 60 раз, а известный расход двух успешных вызовов составил
8 364 токена и примерно $0.0008364 по тарифу. Это не подтверждение списания денег:
план Mistral может быть бесплатным. Отклонённый вызов не имеет usage, его нельзя объявить бесплатным.
Во втором ответе модель неверно воспроизвела контрольную строку; качество не гарантируется
самим наличием длинного контекста. Эксперимент измеряет расход и поведение, а не оценивает интеллект.

DeepSeek Flash: 141 input + 4 output = 145, вернулся ID `deepseek-flash`.
DeepSeek Pro: 140 + 4 = 144, вернулся `deepseek-v4-pro`. Оба работают через HTTP-приложение.
Детальные снимки: `day8-mistral-results.json`, `day8-flash-results.json`, `day8-pro-results.json` рядом.

## Тарифы и источники

Стоимость хранится со снимком тарифов на момент запуска, используется Decimal.
DeepSeek имеет peak/off-peak по UTC: будни 01–04 и 06–10 — peak, остальное время — половина
peak-тарифа. Alias Flash учитывается по фактически возвращённой модели. Провайдер может
менять маршрутизацию и цены: проверяйте каталог, прежде чем использовать оценку как финансовый факт.

- [DeepSeek: модели и цены](https://api-docs.deepseek.com/quick_start/pricing/)
- [Ministral 3 3B](https://docs.mistral.ai/models/ministral-3-3b-25-12)
- [Тарифы Mistral](https://docs.mistral.ai/inference/pricing)
- [Ограничения Mistral](https://docs.mistral.ai/resources/known-limitations)
- [Официальный tokenizer](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512)

## Архитектура и следующий день

`DialogueAgent` остаётся одной сущностью. Его фабрика собирает собственные policies/validators,
стратегию контекста, транспорт и подключаемый `TokenAccounting`. Хранение истории — порт
`ConversationStore`, метрик — `UsageRepository`. HTTP/UI не строят системный промпт и историю.
Подробности модуля: `src/capabilities/token_accounting/README.md`.

Для Дня 9 потребуются стратегия summary, отдельное хранение summary и учёт дополнительных
вызовов сжатия. «Полная история» и «история со summary» будут конфигурациями, не копиями агента.
Это сравнение двух способов контекста, а не «с памятью / без памяти».
