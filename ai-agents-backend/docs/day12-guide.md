# День 12 — персонализация ассистента

Ветка `ai-challenge-day-12` создана от локального checkpoint Дня 11 `cd1aed2`.
Реализована персонализация алгоритмического наставника поверх трёх слоёв памяти.
Диалоговый агент Дней 6–10 не изменяет поведение и не требует профиля.
FSM, инварианты и контролируемые переходы Дней 13–15 пока не реализованы.

## Что можно сделать в UI

1. Открыть http://localhost:8083/ и выбрать «Алгоритмический наставник».
2. Создать задачу: в форме указать условие, N последних сообщений и профиль.
3. В правой панели раскрыть «Профили и предпочтения», посмотреть или изменить настройки.
4. Создать собственный профиль. Он станет выбором по умолчанию для следующей задачи.
5. Отправить запрос и посмотреть использованный профиль в технической информации.
6. Скачать MD-отчёт с памятью, версиями профиля, снимками вызовов и токенами.

Профиль выбирается **один раз при создании задачи**. Редактор может показывать другой
профиль, но не перепривязывает к нему текущую задачу. Заголовок чата показывает
фактическую привязку. Настройки выбранного профиля менять можно: они применяются
к следующим запросам всех его задач, но не переписывают старые ответы и снимки.

## Поля профиля

| Поле | Назначение |
| --- | --- |
| Имя | Метка локальной персоны, не роль и не разрешения |
| Язык объяснения | Русский или английский |
| Уровень опыта | Начинающий, средний, продвинутый |
| Подробность | Кратко, сбалансированно, подробно |
| Формат | Связный текст, список, шаги |
| Предпочитаемый язык кода | Python, Java, JavaScript, Go или без предпочтения |
| Мягкие ограничения | До 8 текстовых пожеланий, каждое до 400 символов |

Например, «объясняй новые термины» и «приводи один небольшой пример» — пожелания
к подаче. Это не жёсткие бизнес-инварианты Дня 14 и не новые системные инструкции.
Никакого дополнительного max_tokens профиль не устанавливает.

Начальные профили:

- `local` — прежний локальный профиль с нейтральными настройками; его память сохранена.
- `beginner` / «Новичок» — подробно, пошагово, с объяснением терминов и примером перед кодом.
- `experienced` / «Опытный разработчик» — кратко, списком, без базового синтаксиса,
  с оценкой временной и пространственной сложности.

## Как профиль попадает в запрос

Обычный запрос наставника строится в следующем порядке:

1. Системные правила агента.
2. Отдельный блок профиля: имя и актуальные предпочтения.
3. Рабочая память текущей задачи.
4. Активные долговременные записи только её профиля.
5. Последние N сообщений диалога.
6. Текущий вопрос пользователя, ровно один раз.

Профиль передаётся как данные в user-блоке, а системные правила описывают,
как его учитывать. Он также включается в отдельный запрос предложений памяти:
схема служебного JSON всегда обязательна, предпочтение «списком» её не заменяет.
LLM не может самостоятельно сохранить или изменить настройки профиля.
Такие операции выполняются только через явную форму/API.

Приоритет: правила агента и схема → подтверждённые ограничения задачи →
явная текущая просьба о языке/стиле → мягкие предпочтения профиля.
Например, при предпочтении Python и обязательном Java в условии нужен Java.
Просьба «ответь одним предложением по-английски» меняет конкретный ответ,
но не сохранённые настройки русского языка и подробного объяснения.
Семантическое соблюдение пожеланий зависит от LLM; абсолютной гарантии здесь нет.

## Хранение и версии

Таблица `profiles` расширяется миграцией `012_personalization.sql`. В ней отдельно
хранятся JSON предпочтений и их версия. Диалог, рабочая память и долговременные
записи остаются в прежних таблицах. Миграция применяется один раз: перезапуск
не сбрасывает отредактированные начальные профили.

- `UserProfile.revision` — имя/предпочтения.
- `UserProfile.memory_revision` — долговременные записи этого профиля.
- `MemoryVersions.task_revision` — рабочая память задачи.
- `MemoryVersions.profile_revision` — прежнее имя версии **долговременной памяти**.
- `MemoryVersions.preferences_revision` — новая версия имени/предпочтений.

Сохранение требует ожидаемой версии. Устаревшая форма получает 409, а не затирает
чужие правки. Если профиль или память изменились, пока LLM отвечала, ответ не
публикуется как актуальный. Расход вызова и использованный снимок сохраняются.
В технической информации у каждого вызова есть собственный снимок профиля,
а локальная оценка токенов профиля отделена от фактического usage API.

Новый профиль не копирует чужие долговременные записи. Задачи одного профиля могут
использовать его общую долговременную память, но не рабочие данные друг друга.
Профили — локальные персоны для эксперимента, **не аккаунты пользователей**:
аутентификация, разграничение доступа, удаление и перепривязка профилей не добавлены.

## Сценарий для видео и сравнения

Создайте две новые задачи с одинаковыми моделью, N=4, условием и без активных
долговременных заметок. Различаться должен только профиль: новичок / опытный.
Условие: найти два разных индекса элементов массива с суммой target; если пары
нет, вернуть пустой список; не менять входной массив; допустима любая верная пара.

Одинаковый запрос:

> Объясни, как найти индексы двух разных элементов массива с суммой target за O(n).
> Для [2,7,11,15] и target=9 дай алгоритм, пример и оценку сложности.

Сравните объяснение терминов, детализацию, порядок примера/кода и объём ответа.
Затем новичку отправьте просьбу ответить одним предложением на английском.
Убедитесь, что конкретный ответ изменился, а сохранённый профиль — нет.
Для проверки редактирования создайте отдельный профиль, измените его настройки,
перезапустите backend и откройте ту же задачу: привязка и настройки сохранятся.

### Реальная проверка DeepSeek

Выполнены три платных API-вызова скриптом `scripts/check_day12.py`.
Запрошена `deepseek-v4-flash`, provider response model — `deepseek-flash`.

| Вызов | Вход API | Выход API | Время |
| --- | ---: | ---: | ---: |
| Новичок, первый вопрос | 808 | 1107 | 5171 мс |
| Опытный, тот же первый вопрос | 811 | 510 | 2598 мс |
| Новичок, явная смена языка/длины | 1939 | 36 | см. метрики вызова |

Всего — 5211 токенов API. Третий запрос дороже по входу из-за накопленной истории.
Новичок получил подробные шаги, объяснение хеш-таблицы и пример перед кодом.
Опытный — более короткое описание, код и сложность. Переопределение дало одно
английское предложение без изменения профиля. Это конкретный эксперимент,
а не обещание одинаковых ответов или фиксированной скорости при повторении.
Сгенерированный код автоматически не исполнялся.

Чаты «День 12 — Новичок» и «День 12 — Опытный разработчик» оставлены для просмотра.
Через UI также созданы «Проверка UI — профиль» и «День 12 — проверка формы».
Тестовый профиль изменён через форму до версии 2: добавлено «Объясняй без жаргона.».
После пересборки и пересоздания backend обе настройки и привязка задачи восстановились;
это проверено через API и повторным открытием панели в браузере.

## Запуск и проверки

Для отдельного набора данных Дня 12, когда портами владеет День 11:

```powershell
docker compose -p ai-chat-day-11 stop agents-client agents-backend
docker compose -p ai-chat-day-12 up -d --build agents-backend agents-client
```

Отдельный Compose project создаёт отдельный том; том Дня 11 не удаляется.
Для обновления существующей БД сначала сделайте резервную копию. Миграция старой
схемы Дня 11 проверяется отдельным автоматическим тестом без потери её данных.

Из соответствующих папок проектов:

```powershell
# ai-agents-backend
.venv\Scripts\python.exe -m pytest
# ai-agents-client
pnpm test
pnpm build
```

Результат: 98 backend-тестов, 50 frontend-тестов; production-сборка и Docker успешны.
Проверяются версии, состав prompt, изоляция, неизменяемая привязка, конфликт во
время вызова, совместимость прежнего агента и восстановление после перезапуска.
Для повторения реального теста (расходует API, создаёт демонстрационные чаты):

```powershell
.venv\Scripts\python.exe scripts/check_day12.py --allow-llm
```

Скрипт использует 1200 выходных токенов только как предел своего эксперимента;
это не новое значение по умолчанию приложения. Ключи и SQLite остаются вне Git.
