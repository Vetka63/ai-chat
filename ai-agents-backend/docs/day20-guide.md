# День 20-v2: оркестрация нескольких MCP-серверов

## Что сделано

Новый агент «MCP-оркестратор · День 20» ведёт обычный чат и по необходимости
использует инструменты трёх независимых HTTP MCP-серверов:

| Сервер | Язык | Инструмент | Назначение |
| --- | --- | --- | --- |
| java-mcp-games | Java | search_games | Поиск в учебном SQL-каталоге игр |
| python-mcp-game-reports | Python | summarize_games, compose_report | Сводка выбранной подборки и черновик отчёта из выбранных сводок |
| go-mcp-report-store | Go | save_report | Сохранение готового Markdown в отдельном томе |

`workspace__save_collection` — локальный шаг агента, а не четвёртый MCP-сервер.
Он выбирает игры из результата поиска и сохраняет подборку. Каждый сервер
можно включить или отключить для конкретного сообщения в меню MCP у поля ввода.
Без подключённых MCP агент всё равно отвечает на общие вопросы.

## Длинный сценарий

1. Пользователь просит две космические игры. Модель выбирает
   `java_games__search_games`, видит реальный ответ, затем
   `workspace__save_collection`. Создаётся подборка «Космос».
2. Аналогично создаётся отдельная подборка «Сад».
3. По просьбе пользователя модель вызывает `python_analysis__summarize_collection`
   для каждой подборки. Python MCP возвращает две независимые сводки.
4. Можно дополнительно найти игру про машину. Поиск сохранится как отдельный
   артефакт, но не попадёт в отчёт автоматически.
5. Пользователь просит отчёт только из двух сводок. Модель указывает их ID
   в `python_analysis__compose_report`. Бэкенд загружает именно эти сводки,
   проверяет их принадлежность чату и передаёт Python MCP. После явной просьбы
   сохранить модель вызывает `go_reports__save_report`. Go MCP сохраняет
   Markdown и возвращает подтверждение. UI показывает файл и кнопку
   «Скачать MD».

Это не заранее жёстко запущенная цепочка из трёх вызовов. На каждом шаге
модель получает результат предыдущего шага и выбирает следующий из
доступных инструментов. Бэкенд не доверяет её аргументам без проверки:
проверяет типы, существование ID, принадлежность чату, порядок этапов и
факт подключения нужного MCP. За один шаг допускается один вызов, всего
не более девяти шагов на сообщение. Результаты вызовов видны в истории чата,
а потребление токенов сохраняется для каждого LLM-вызова.

## Где хранятся данные

- Сообщения, MCP-события и артефакты лежат в SQLite Python-бэкенда.
  Артефакты имеют тип `search`, `collection`, `summary`, `draft`, `report`,
  ID, ссылки на источники и ID чата.
- Игры живут в SQL-хранилище `mock-games-server`. Агент не создаёт новые
  игры; Java MCP только читает каталог.
- Физические Markdown-файлы сохраняет Go MCP в томе `go-report-data`.
  Копия содержимого подтверждённого отчёта остаётся в артефакте чата,
  поэтому UI может скачать её после перезапуска бэкенда.
- Чаты изолированы: ID артефакта из другого чата не принимается.

Сохранение отчёта разрешено только при явной просьбе в текущем сообщении.
Одна лишь просьба сохранить **подборку** не считается просьбой сохранить
**отчёт**. Если Go MCP отключён, агент не должен утверждать, что файл создан.
Удаление чата очищает его SQLite-артефакты, но уже сохранённый файл в
отдельном томе Go MCP пока не удаляет — это ограничение учебной версии.

## Запуск рядом с днём 19

Из корня репозитория в PowerShell:

```powershell
$env:PY_AGENTS_API_PORT='8282'
$env:PY_AGENTS_UI_PORT='8283'
$env:PY_GAMES_API_PORT='8284'
$env:JAVA_GAMES_MCP_PORT='8285'
$env:PY_GAMES_MCP_PORT='8286'
$env:PY_GAME_FEED_MCP_PORT='8287'
$env:PY_GAME_REPORT_MCP_PORT='8288'
$env:GO_REPORT_MCP_PORT='8289'
docker compose -p ai-chat-day-20-v2 up -d --build agents-client game-feed-worker
```

UI: http://localhost:8283/. Это отдельный Compose-проект с отдельными томами;
запущенный день 19 на портах 818x не затрагивается. Нужен настроенный
DeepSeek API-ключ в локальном `.env` для живых LLM-вызовов. Ключ не
передаётся ни в MCP, ни в Git.

## Проверка через UI

1. Выберите «MCP-оркестратор · День 20», создайте новый чат. Подключите
   «Игры · Java», «Игровые отчёты · Python» и «Сохранение отчётов · Go».
2. «Найди в нашем каталоге две игры про космос и сохрани их как подборку
   „Космос“». Ожидаются Java-поиск и подборка с двумя играми.
3. «Найди две игры про сад и сохрани их как подборку „Сад“». Должна
   появиться вторая подборка.
4. «Сделай отдельную сводку по подборке „Космос“», затем аналогично для
   «Сад». Появятся две сводки, каждая с двумя играми, и вызовы Python MCP.
5. «Найди игру про машину, но не добавляй её ни в одну сводку». Поиск
   появится, число сводок не изменится.
6. «Составь и сохрани итоговый Markdown-отчёт только по двум сводкам
   „Космос“ и „Сад“. Игру про машину не включай». Должны последовательно
   появиться вызовы Python `compose_report` и Go `save_report`.
   В отчёте — две сводки, без машины. Скачайте MD.
7. Обновите страницу: подборки, сводки, отчёт и след MCP-вызовов останутся.
   В новом чате этих артефактов не будет.
8. Отключите Go MCP для следующего сообщения и попросите сохранить
   новый отчёт. В следе не должно быть `go_reports__save_report`;
   агент не должен заявить об успешном сохранении.

Автопроверки: тесты Python-бэкенда и Python MCP, `go test ./...`,
`pnpm test` и `pnpm build`. Интеграционный тест проверяет два набора игр,
две сводки, постороннюю игру, выбор источников, порядок вызовов трёх
серверов и изоляцию чатов.
