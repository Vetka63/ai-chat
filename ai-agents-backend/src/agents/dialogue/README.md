# Диалоговый агент · Дни 6–8

DialogueAgent — самостоятельная сущность. HTTP-контроллер выбирает её в реестре,
но не составляет промпт, не вызывает провайдера и не применяет политики.

## Сценарий одного сообщения

1. AgentCommand содержит conversation_id, message и необязательный model_id.
2. Собственные TrimInputPolicy и NonEmptyInputValidator готовят и проверяют текст.
   Ограничения количества символов или токенов в агенте нет.
3. Агент загружает полную историю из ConversationStore. Модель выбирается из команды,
   сохранённой настройки чата либо конфигурации агента; проверяется серверный каталог.
4. FullHistoryContextPolicy формирует system → history → новый user.
5. Подключаемый TokenAccounting измеряет контекст без изменения и блокировки.
6. Вопрос сохраняется в SQLite до HTTP-вызова. При ошибке провайдера он не исчезает.
7. LlmClient вызывает выбранную модель. Router и детали API находятся вне агента.
8. OutputPolicy обрабатывает ответ, NonEmptyOutputValidator отклоняет пустой вывод.
9. Успешный ответ сохраняется. RunRecord содержит статус, оценки, usage, время,
   finish_reason, тариф и стоимость. Даже пустой ответ может иметь оплаченные токены.

Системный промпт взят за основу из Java general-профиля; {provider} заполняется
по выбранной модели. Адаптер DeepSeek отключает thinking; Mistral этого параметра не получает.

## Расширение

Фабрика принимает context_policy и accounting как зависимости. Свои input/output
policy, validators и при необходимости judge остаются в пакете конкретного агента.
Общий модуль не содержит бизнес-правил этого агента. Учёт токенов можно отключить,
не отключая память; стратегию контекста можно заменить, не копируя класс.

Для N агентов создавайте независимые конфигурации/фабрики и регистрируйте их в
AgentRegistry. agent_id изолирует историю и метрики. Состояние разговора хранится
по conversation_id, а не в экземпляре агента. При выносе агента в сервис заменяются
адаптеры портов; приватные правила остаются у агента.

Нынешняя SQLite/lock-реализация — один процесс, не распределённые 100 workers.
Это отдельный следующий шаг масштабирования, не часть Дня 8.
