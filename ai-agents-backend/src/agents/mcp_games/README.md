# Игровой MCP-агент

`McpGamesAgent` инкапсулирует чат Дня 17: при создании задаёт начальный набор
доступных MCP-серверов, а на каждом ходе принимает независимый выбор из UI.
Пустой набор отключает инструменты для этого хода. Агент сохраняет вопрос
вместе с выбранными ID, обнаруживает инструменты, передаёт
их модели, проверяет её `tool_calls` по разрешённому списку, выполняет MCP,
сохраняет результат и запрашивает итоговый ответ модели. Системная инструкция
лежит в `prompts.py`; публичный HTTP-роутинг остаётся в `application/main.py`.
Если инструменты отключены, обычный LLM-вызов всё равно выполняется: модель
отвечает по своим знаниям и истории диалога, не предлагая подключить MCP.

Для расширения на другие инструменты не нужно копировать агента: добавьте
разрешённый сервер в каталог `capabilities/mcp_discovery/service.py` и его
специализированный MCP-адаптер. Агент работает с объявлениями инструментов
и нормализованными результатами, а не с конкретным HTTP API игр.

## Автоматический выбор поиска

Выбранный в UI MCP-сервер **разрешает** модели видеть `search_games`, но не
заставляет её вызывать поиск на каждом ходе. Первый запрос к DeepSeek идёт с
`tool_choice=auto`. Если модель вернула `tool_calls`, агент проверяет имена
по разрешённому списку, выполняет `tools/call` и запрашивает итоговый ответ.
Правило в `prompts.py` и описание инструмента на обоих MCP-серверах предлагают
поиск при явной просьбе проверить **наш** каталог или при вопросе о конкретной
игре, о которой у модели нет надёжных сведений.
Например, «что такое RPG?» и «придумай игру» не требуют поиска, а
«найди у нас игры про космос» требует. При вопросе «знаешь игру „Звёздные
тропы“?» модель может сама обратиться к каталогу, если не знает ответа.
Пустой результат означает только отсутствие игры в учебном каталоге.

Если модель вместо вызова инструмента ответила, что не знает конкретную игру,
или заявила о наличии/отсутствии игры в каталоге без проверки,
`lookup_policy.py` не оставляет этот ответ финальным. При включённом MCP агент
делает **одну** повторную попытку с `tool_choice=required`, передавая только
разрешённые инструменты `search_games`. Та же подстраховка действует для явной
просьбы проверить каталог. Общие вопросы, известные игры, творческие задания
и просьбы именно о веб-поиске её не запускают. Если MCP выключен, нет ни
`tools/list`, ни повторной попытки. Отдельные LLM-вызовы сохраняются с
назначениями `mcp_selection`, `mcp_selection_retry` и `mcp_answer`, чтобы
расход токенов был виден. В истории чата остаётся только итоговый ответ,
а не промежуточное «не знаю».

`search_games` обращается к учебному каталогу, а не к интернету. Веб-поиск
через текущий Chat Completions-запрос этому агенту не предоставлен. Поэтому
актуальные сведения нельзя выдавать за проверенные, если нет подходящего
внешнего источника. Демо-режим без LLM отвечает лишь на простые заранее
заданные вопросы и показывает цикл вызова каталога.

Подстраховка устраняет отказ от поиска, когда модель сама признала нехватку
знаний, но не может обнаружить уверенно написанную галлюцинацию. Для такой
проверки потребуется отдельная оценка достоверности или правило обязательного
поиска для всех запросов о конкретных играх. Последнее увеличит число
MCP-вызовов и может затронуть известные игры.
