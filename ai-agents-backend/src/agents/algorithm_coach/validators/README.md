# Локальные проверки обязательных правил

`invariants.py` содержит предметную `CoachInvariantPolicy`:

- проверка допустимости конфигурации (Python, сигнатура, разрешённые импорты);
- AST-разбор Python-кода без исполнения;
- сравнение сигнатуры и разрешённых корней импортов;
- консервативный отказ при поддерживаемых формах динамической загрузки;
- ошибки синтаксиса дают uncertain, а не разрешение.

Это не sandbox и не доказательство корректности: семантика, произвольные обходы,
сложность и неизменность входа требуют отдельной проверки. Текст без кода сам
по себе не обязан содержать сигнатуру. Полное решение проверяется строже.
Валидатор подключён к ответам и ручным артефактам через `InvariantGuard`.
Локальный конфликт/неопределённость сразу блокирует кандидат, без вызова judge.
При отсутствии локального отказа вызывается semantic judge с отдельной моделью.
Фрагменты кода должны быть синтаксически полными: даже иллюстративный фрагмент
с запрещённым импортом будет консервативно отклонён. Обсуждайте такие примеры
текстом. Подпись сравнивает также аннотации/defaults; helper-функции допустимы,
если требуемая функция присутствует в том же блоке.

`stages.py:CoachStagePolicy` добавляет системное правило `workflow-stage`.
Оно запрещает реализацию до утверждения плана и новую реализацию на validation
до возврата на доработку. Очевидные блоки кода отклоняются локально; скрытая
реализация и соответствие плану проверяются judge. Локальная проверка намеренно
консервативна: на planning/validation обсуждайте код словами. Это не доказательство
отсутствия всех возможных обходов. Правило не хранится в редактируемом списке
пользовательских инвариантов, но входит в снимок аудита каждой проверки.
