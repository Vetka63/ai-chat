# Подключаемый учёт токенов

Этот модуль измеряет уже подготовленный запрос, но **не решает, какую историю отправлять**.
Не обрезает сообщения, не делает summary, не отклоняет переполнение. Поэтому его можно
подключать к N агентам независимо от их собственных input/output policy и validators.

- `models.py`: Pydantic-контракты оценки, usage, тарифа и сохранённого запуска.
- `service.py`: `TokenAccounting`, формула стоимости и порты `TokenEstimator`, `UsageRepository`.
- Адаптеры находятся в `infrastructure/tokenizers.py` и `infrastructure/sqlite_usage.py`.
- Подключение — `application/bootstrap.py`; агенту передаётся `accounting=...` в фабрике.
  Без accounting агент продолжает отвечать, но не сохраняет метрики; preview вернёт 501.

## Сценарий

1. Агент получает исходную историю из ConversationStore.
2. Его ContextPolicy строит список messages.
3. `estimate(messages, history, text, model, max_tokens)` измеряет этот список.
4. До вызова сохраняется RunRecord со статусом pending и снимком тарифа.
5. Адаптер LLM нормализует usage и finish_reason.
6. Агент сохраняет success/error, связь с индексами сообщений, длительность и реальные usage.
7. `record` рассчитывает стоимость и обновляет запись. При перезапуске pending становится interrupted.

## Что именно считается

Раздельные `current_message_tokens`, `history_tokens`, `system_tokens` — токены текстов,
без служебной разметки чата. `prompt_tokens` в estimate — весь сериализованный контекст
со служебными токенами. Они не обязаны равняться сумме отдельных текстов.
Фактические `usage.prompt_tokens`, `completion_tokens`, `total_tokens` приходят от API.
Кэш — часть input; reasoning — часть output; повторно их не прибавляем.

Стоимость USD = ((input − cached) × input_price + cached × cache_price + output × output_price) / 1 000 000.
Используется Decimal. Если usage отсутствует — стоимость null, а не 0.
Если размер кэша неизвестен — вход считается по cache-miss тарифу (консервативная оценка).
Бесплатный план провайдера может означать отсутствие списания, но не отсутствие токенов.

Менять нужно стратегию ContextPolicy, а не копировать DialogueAgent. Исходная история
остаётся в хранилище, summary будет храниться отдельно. Учёт измерит именно тот messages,
который построит стратегия. Вызовы модели для создания summary тоже надо будет учитывать
отдельно: нынешний День 8 измеряет только разговорные вызовы. Само сжатие ещё не реализовано.

## Ограничения

SQLite и asyncio-lock рассчитаны на один процесс uvicorn. Для нескольких workers/реплик
нужны межпроцессная блокировка по conversation_id и lease для pending-запусков.
Для отдельного сервиса можно заменить UsageRepository и транспорт, не менять формулу расчёта.
Точность DeepSeek до вызова ограничена эвристикой; оценка не является основанием для блокировки.
