# Жизненный цикл задачи

Общий механизм Дней 13 и 15. Конкретный граф и схемы артефактов принадлежат агенту:
`agents/algorithm_coach/workflow_policy.py`. Здесь нет правил Two Sum.

- `models.py` — состояние, снимок, артефакт и команды с ID/ожидаемой версией.
- `contracts.py` — порт Unit of Work для атомарного сохранения.
- `service.py` — прикладной вход, соединяющий порт с политикой.
- `infrastructure/sqlite_task_workflow.py` — SQLite-адаптер.
- `application/routes/tasks.py` — HTTP-вход. Произвольного PATCH phase нет.

Фаза и пауза — разные поля. `current_step_id` ссылается на шаг плана;
`expected_action` вычисляет политика, а не LLM. Каждая версия артефакта неизменяема.
Состояние и последние артефакты включаются в рабочий блок prompt; весь журнал
переходов и все старые версии в модель не отправляются.

Команды UI/API имеют `command_id` и `expected_revision`. Повтор успешной команды
возвращает её сохранённый результат; иной payload с тем же ID — конфликт.
Вопрос и reservation сохраняются вместе. Один pending основной run на задачу
защищён уникальным индексом. Успех атомарно сохраняет ответ, run, событие и replay-кэш.
Пауза меняет версию независимо от HTTP-вызова LLM. Поздний ответ отклоняется,
но расход не теряется. Ошибка не продвигает автомат и не запускает retry провайдера.

После рестарта pending-команды и pending-метрики становятся interrupted.
Автоматического повторного платного вызова нет. Неизвестный расход не равен нулю.
Recovery рассчитан на один процесс приложения: несколько независимых worker
с собственным startup-recovery пока не поддерживаются.

День 15 добавляет условия переходов и подтверждение точного `artifact_id`:
план → утверждение → решение → передача на проверку → отчёт без блокеров → принятие.
`allowed_events` содержит только доступные действия, `blocked_events` — причины,
почему действие текущей фазы пока недоступно. API проверяет их заново в транзакции.

Состояние хранит ID/версии утверждённого плана, отправленного решения и принятого
отчёта. Изменение рабочей памяти, условия или инвариантов сбрасывает утверждения,
возвращает planning и требует нового плана; старые версии не удаляются. Пауза
сохраняется. Доработка сохраняет замечания и шаг, но требует новой версии решения
и отчёта. Профиль и долговременные заметки не сбрасывают утверждение плана.

Старые артефакты имеют `checked_workflow_version=14` и не получают новых гарантий
задним числом. Старые execution/validation без approval сохраняют состояние,
но требуют явного перепланирования. Fingerprint включает версию протокола 15:
команда старого протокола не воспроизводит устаревший результат как новый.
Нет исполнителя кода. [Подробный сценарий](../../../docs/day15-guide.md).
