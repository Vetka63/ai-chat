# MCP Discovery · День 16

Этот пакет не зависит от диалога, памяти или LLM. Он проверяет отдельный MCP-флоу:
подключиться к серверу и запросить объявления его инструментов.

- `demo_server.py` — локальный учебный MCP-сервер с `add_numbers` и `echo_text`.
  Это реальные MCP tools, но День 16 их **не вызывает**.
- `service.py` — фиксированный каталог разрешённых серверов и MCP-клиент. Для
  `local-demo` клиент запускает сервер как дочерний процесс через `stdio`, входит
  в `async with Client(...)`, запрашивает все страницы `tools/list` и закрывает
  соединение. У цикла есть защита от повторяющегося курсора, у всей операции —
  таймаут 10 секунд.
- `models.py` — модели каталога и результата для HTTP API.
- `__main__.py` — проверка без UI: вывод результата в JSON.

Каталог возвращает только безопасные сведения о сервере. Команда запуска и её
аргументы остаются на бэкенде: браузер не может запустить произвольный процесс.
SDK передаёт дочернему процессу ограниченный список переменных окружения;
наши LLM-ключи серверу не нужны и явно ему не передаются.

HTTP-слой находится в `application/routes/mcp.py`:

- `GET /api/v1/mcp/servers` — разрешённые серверы;
- `POST /api/v1/mcp/servers/local-demo/discover` — проверка соединения и список tools.

Сейчас это краткоживущее соединение для обнаружения инструментов. Вызовы
инструментов, удалённые MCP-серверы, авторизация и передача tools модели —
отдельные будущие задачи. Новый сервер добавляется в каталог на бэкенде,
не в параметры запроса от клиента.
