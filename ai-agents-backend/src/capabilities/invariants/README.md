# Обязательные правила задачи

Модуль не знает предметной области. `models.py` содержит Pydantic-контракты
правил, команд, вердиктов и аудита. `contracts.py` — границы хранилища и judge.
`service.py:InvariantGuard` сочетает переданную предметную policy с judge.

Порядок проверки: активные правила → локальные проверки (для кода) → semantic
judge, если локального отказа нет → сохранение аудита → проверка актуальности
версий → разрешение или типизированный policy-refusal. На input нет AST-проверки:
цитирование плохого кода в вопросе не равно просьбе его реализовать.

`conflict` сильнее `uncertain`, а `uncertain` сильнее `pass`. Ошибка/неполный JSON
judge означает uncertain, никогда не разрешение. Нет активных правил — нет
дополнительных вызовов. Локальные проверки не обязаны возвращать pass каждого
правила: при отсутствии отказа все правила проверяет judge.

Предметная реализация находится в `agents/algorithm_coach/validators` и
`agents/algorithm_coach/llm_judge`. SQLite-адаптер — `infrastructure/sqlite_invariants.py`.
Новый агент может подключить свои policy/judge; переносить правила алгоритмов
в общий слой не требуется. Полное описание: `docs/day14-guide.md`.
