# Input

Модуль формирует сообщения для LLM из текущего ввода и разрешённой истории.
Он применяет лимиты профиля, запрещает неподдерживаемые роли и только на сервере
добавляет системный промпт и инструкцию выбранного режима ответа.

`InputPolicy` — расширяемый интерфейс, `InputPolicyRegistry` выбирает реализацию
по `input_policy.type`, а `StandardInputPolicy` содержит текущее поведение.
Политики принимают собственную модель `InputHistoryMessage` и не зависят от HTTP
DTO или `task/chat`. Клиент не может передать роль `system` или заменить
серверные инструкции.

Настройки находятся в `input_policy` YAML-профиля. Логика семантического допуска
сюда не входит — она принадлежит `common/validator` и конкретной задаче.
