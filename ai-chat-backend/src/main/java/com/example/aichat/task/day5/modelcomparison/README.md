# День 5: сравнение версий моделей

Домен выполняет одну и ту же задачу на трёх моделях и возвращает сопоставимые
ответы, время API-вызова, usage и расчётную стоимость:

| Уровень | Провайдер | API-модель |
|---|---|---|
| слабая | Mistral | `ministral-3b-2512` |
| средняя | DeepSeek | `deepseek-v4-flash` |
| сильная | DeepSeek | `deepseek-v4-pro` |

Названия уровней относятся только к учебной шкале этого эксперимента и не
являются универсальным рейтингом моделей.

## Поток запроса

```text
POST /api/model-comparisons
  -> ModelComparisonController
  -> ModelComparisonService
       -> ModelComparisonConfigProvider читает feature_config
       -> создаётся один неизменяемый список system + user messages
       -> LlmProviderRegistry выбирает MistralClient или DeepSeekClient
       -> три последовательных API-вызова
       -> ModelCostCalculator применяет тариф соответствующей модели
  -> ModelComparisonExperiment

POST /api/model-comparisons/judge
  -> отдельный обезличенный вызов DeepSeek Pro
  -> ModelComparisonJudgeResult
```

Запросы выполняются последовательно, чтобы не смешивать результаты с разным
параллельным давлением на provider rate limits. Ошибка одной модели превращается
в `status: error`; ответы остальных моделей сохраняются.

## Что одинаково

Для каждой модели используются один system prompt, дословно одна задача,
`temperature: 0`, `top_p: 1`, `max_tokens: 1200`, пустая история и обычный
текстовый ответ. У DeepSeek явно отключается thinking. Mistral-запрос не получает
DeepSeek-специфичные поля `thinking` и `reasoning_effort`.

## Провайдеры

`LlmProviderRegistry` находится в `common/llm` и индексирует реализации
`LlmProviderClient`. `DeepSeekClient` одновременно сохраняет старый контракт
`LlmClient`, поэтому Дни 1–4 не зависят от нового Mistral-адаптера.

Для Mistral используются отдельные переменные:

```dotenv
MISTRAL_BASE_URL=https://api.mistral.ai/v1
MISTRAL_API_KEY=...
```

Секрет не хранится в YAML. Если Mistral-ключ отсутствует, только слабый вариант
завершается ошибкой, а оба DeepSeek-вызова продолжают выполняться.

## Метрики и стоимость

`MistralClient` и `DeepSeekClient` преобразуют provider usage в общий `LlmUsage`.
`ModelCostCalculator` считает cache miss, cache hit и output по отдельным ценам,
делит сумму на миллион и округляет её до восьми знаков после запятой.

Тарифы зафиксированы в `day5-model-comparison.yml` на 4 сентября 2026 года:
Mistral Standard и DeepSeek Peak — консервативная верхняя оценка. Это расчёт, а
не сумма фактического списания. Тарифы могут измениться, поэтому YAML содержит
ссылки на официальные страницы и должен обновляться вместе с ними.

Сравнение токенов ориентировочное: разные семейства моделей могут использовать
разные токенизаторы. Время включает HTTP-запрос и зависит от сети, очереди и
нагрузки провайдера; один запуск не является производительным бенчмарком.

## Клиентский результат

UI показывает три карточки, автоматически выделяет самую быструю, экономную по
токенам и дешёвую модель. Качество можно оценить вручную по шкале 1–5 и через
отдельного AI-судью. Судья вызывается только по кнопке, обезличенно оценивает
точность, соблюдение задачи, полноту и ясность, выбирает победителя и формирует
краткий вывод. Это четвёртый платный вызов, его метрики выводятся отдельно.

DeepSeek Pro оценивает в том числе собственный ответ, поэтому его решение не
считается абсолютно объективным. Ручной выбор сохраняется и показывается рядом
с рекомендацией судьи. Детали находятся в `llmjudge/README.md`.

Кнопка «Скачать Markdown» сохраняет ответы, метрики, ручные оценки, результат и
расходы судьи, короткий вывод и официальные ссылки в
`day5-model-comparison-<id запуска>.md`.
