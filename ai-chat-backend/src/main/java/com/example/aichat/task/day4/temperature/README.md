# День 4: температура

Домен демонстрирует влияние `temperature` на один и тот же запрос. Backend
выполняет четыре независимых вызова со значениями `0`, `0.7`, `1.2` и `2.0`, а frontend
показывает ответы рядом и помогает вручную сравнить точность, креативность и
разнообразие.

## Что именно остаётся одинаковым

Для чистоты эксперимента каждый вызов получает:

- один и тот же system prompt;
- дословно одну пользовательскую задачу;
- одну модель `deepseek-v4-flash`;
- одинаковые `top_p`, `max_tokens`, thinking и формат ответа;
- пустую историю диалога.

Меняется только `temperature`. Поэтому различия ответов можно связывать именно
с этим параметром, а не с разными инструкциями или контекстом.

## Поток выполнения

```text
POST /api/temperature-experiments
  -> TemperatureExperimentController
  -> TemperatureExperimentService
       -> TemperatureConfigProvider читает feature_config
       -> AgentLlmRequestFactory создаёт базовый запрос
       -> LlmRequestOverrides меняет только temperature
       -> LlmClient вызывается последовательно четыре раза
  -> TemperatureExperiment с результатами и общими метриками
```

Последовательный запуск выбран намеренно: одновременные запросы могли бы по-разному
попасть под нагрузку или rate limit провайдера. Порядок ответа всегда совпадает с
порядком вариантов в YAML.

## Состав пакета

- `controller` — HTTP endpoint;
- `controller/dto` — входной контракт запуска;
- `service` — оркестрация четырёх вызовов;
- `config` — типизированная конфигурация `feature_config`;
- `model` — результат эксперимента и каждой температуры;
- `llmjudge` — отдельный обезличенный судья, его HTTP-контракт и результат;
- `enums` — статус отдельного результата.

## HTTP API

Запрос:

```http
POST /api/temperature-experiments
Content-Type: application/json
```

```json
{
  "profileId": "day4-temperature",
  "task": "Придумай три названия для приложения учёта домашних растений"
}
```

Сокращённый ответ:

```json
{
  "experimentId": "...",
  "profileId": "day4-temperature",
  "task": "Придумай три названия для приложения учёта домашних растений",
  "results": [
    {
      "id": "precise",
      "temperature": 0.0,
      "status": "success",
      "answer": "...",
      "model": "deepseek-v4-flash",
      "metrics": { "apiCalls": 1, "totalTokens": 150 }
    }
  ],
  "metrics": { "apiCalls": 4, "totalTokens": 620 }
}
```

Метрики результата относятся к одному вызову, верхнеуровневые метрики — ко всему
эксперименту. `elapsedMs` измеряет общее время сценария, а `apiDurationMs`
суммирует время отдельных обращений.

## Конфигурация

Значения и подписи находятся в
`src/main/resources/agents/day4-temperature.yml`:

```yaml
deepseek:
  model: deepseek-v4-flash
  thinking: disabled
  top_p: 1.0

feature_config:
  temperatures:
    - { id: precise, title: Точный, value: 0.0 }
    - { id: balanced, title: Сбалансированный, value: 0.7 }
    - { id: creative, title: Творческий, value: 1.2 }
    - { id: experimental, title: Экспериментальный, value: 2.0 }
  max_tokens: 1200
```

`TemperatureConfigProvider` реализует `AgentFeatureConfigValidator`. При старте
он отклоняет пустой набор, повторяющиеся id или значения, температуры вне
диапазона `0..2` и неверный лимит токенов. Ошибка обнаруживается до первого
пользовательского запроса.

## Частичный отказ

Ошибка DeepSeek у одной температуры не отменяет остальные результаты. Такой
элемент получает `status: error` и безопасное сообщение, а успешные карточки
остаются доступны. В общих метриках `apiCalls` всё равно равен числу предпринятых
вызовов. Неожиданная ошибка программирования не скрывается этим механизмом и
завершает запрос обычной серверной ошибкой.

## Ручное сравнение на клиенте

UI позволяет для каждого успешного ответа поставить оценки точности и
креативности от 1 до 5, выбрать лучший вариант, оценить общее разнообразие и
записать вывод. Эти оценки не отправляются на backend и не сохраняются после
обновления страницы. Кнопка копирования формирует Markdown-отчёт, пригодный для
результата учебного задания.

## Автоматический судья

После генерации минимум двух успешных вариантов клиент может отдельно вызвать:

```http
POST /api/temperature-experiments/judge
Content-Type: application/json
```

```json
{
  "profileId": "day4-temperature",
  "task": "Придумай три названия для приложения учёта домашних растений",
  "candidates": [
    { "variantId": "precise", "answer": "..." },
    { "variantId": "experimental", "answer": "..." }
  ]
}
```

`TemperatureJudgeService` проверяет идентификаторы по конфигурации, обезличивает
ответы кодами `A`–`D` и вызывает `deepseek-v4-pro` с `temperature: 0`. Ответ
валидируется как JSON: оценки должны быть целыми числами `0..10`, каждый
кандидат обязан присутствовать ровно один раз, а победитель должен существовать.
При повреждённом JSON выполняется одна повторная попытка. Детальная схема и
примеры описаны в соседнем `llmjudge/README.md`.
